# 導讀

## 這本書為誰而寫

你會寫程式，可能是 Python、Java 或 JavaScript，也許每天都在寫後端服務。可是當程式出現 segmentation fault、延遲莫名其妙變高、記憶體一直漲、連線偶爾卡住時，你會發現高階語言替你擋掉的那些東西，突然全部回來找你：指標、stack、cache、page fault、file descriptor、signal、race。

這本書就是為這樣的讀者寫的：會寫程式，大學修過或沒修過計算機組織，C 只學過一點，沒用過 `gdb`，但想真正理解「程式在機器上到底怎麼跑」。讀完之後，你應該能看懂 core dump、分析效能瓶頸、處理 link error、寫出正確的 I/O 與網路程式，並找出 race 與 memory leak。

## 和 CS:APP 3e 的關係

本書以 Randal E. Bryant 與 David R. O'Hallaron 的《Computer Systems: A Programmer's Perspective》第三版（CS:APP 3e）為骨架，涵蓋原書全部 12 章的核心觀念。但它**不是原書的摘要或翻譯**，而是重新組織與補充：

- **重新切分**：原書一章常常包含好幾個大主題，本書把它們拆成 34 章，每章只處理一個問題，並用承接句把章與章串起來。
- **自給自足**：每個新名詞第一次出現就白話解釋並舉例，數值類主題都有完整的手算算例。不必另外買原書也能讀懂；原書是延伸閱讀，不是前提。
- **補上現況**：原書出版後的業界變化，例如 ARM64 與 Apple Silicon、sanitizer、現代 allocator、`epoll`、Spectre 與 Meltdown，都放進相關章節。
- **連到工作**：每章都有「在工作上怎麼用」，給出具體的工具指令、判斷流程與檢查清單。這是本書和教科書最大的差別。

每章開頭的「本章地圖」都會標出對應的 CS:APP 3e 章節，想對照原書的讀者可以按圖索驥。

## 全書地圖

全書分成 11 個 Part、34 章，外加 5 個附錄。整體的走向是由下而上：先看資料在記憶體裡怎麼表示，再看 CPU 怎麼執行指令、怎麼存取記憶體，接著看程式怎麼被連結、載入成 process，最後看 process 怎麼和作業系統、檔案、網路以及其他 thread 互動。

 ├────────────────────────────────┴─────────────────────────────────┤

 ├──────────────────────────────────────────────────────────────────┤

讀這張圖時，由下往上是「抽象層次越來越高」：最底下是 C 程式和它的位元，中間是硬體如何執行與存取記憶體，上面是作業系統與網路提供的抽象，最上層把所有東西整合起來。實務上的問題幾乎都會跨好幾層，例如一次「延遲變高」可能同時牽涉 cache（Part 4）、page fault（Part 7）與 lock 競爭（Part 9），第 33 章會示範怎麼一路追下去。

## 貫穿全書的案例：拾光相簿與 `thumbd`

為了讓每一章的知識都有落地的場景，全書使用同一個虛構的服務。**拾光相簿**是一個線上相簿，後端有一個用 C 寫的縮圖服務 `thumbd`：

```text
使用者 ─HTTP→ nginx ─HTTP→ thumbd（C，thread pool）
                             ├─ 解析 HTTP request（第 28–29 章）
                             ├─ 讀原圖檔（mmap／read，第 24、27 章）
                             ├─ 解碼（libjpeg／libpng，動態連結，第 19 章）
                             ├─ 縮放、旋轉（像素矩陣運算，第 14、17 章）
                             ├─ 快取縮圖（malloc／free，第 25–26 章）
                             └─ 回傳結果；用 fork/exec 呼叫外部工具處理少數格式（第 21 章）
```

`thumbd` 的每一個步驟都對應書中的某幾章，所以它幾乎會遇到所有你在工作上可能碰到的系統問題：寬 × 高 × 4 的整數溢位、換了 library 版本後當機、zombie 累積、memory leak、加 thread 反而變慢。

主要人物有兩位。**小安**是剛入職的初階後端工程師，熟悉 Python 與 Java，C 只在大學學過；**老周**是資深系統工程師，`thumbd` 的原作者之一，也是小安的 mentor。偶爾會出現 SRE 阿哲、產品經理 Lisa 等配角。每一章都從 `thumbd` 遇到的一個真實問題開場，讓你先感受到「不懂這一章會卡在哪裡」，再用這一章的知識把它解開。

## 三種讀法

**從頭讀到尾。** 適合學生或想打好完整基礎的人。按照章節順序讀，每章都做「動手做」與至少兩題練習，並搭配第 34 章的 Labs。每週投入 8 到 10 小時，大約 20 週可以讀完（第 34 章有完整時程）；每週能投入 12 到 15 小時的話，可以壓到 16 週（附錄 D）。

**依問題查閱。** 適合已經在工作、手上有具體問題的人。先從第 33 章的「症狀到章節的對照表」（33.10 節）找到相關章節，讀那一章的故事、核心概念與「在工作上怎麼用」；遇到不懂的名詞，用附錄 C 的術語表找到它首次出現的章節補讀。

**以 Labs 為主軸。** 適合想自學 CS:APP、或準備系統類面試的人。先讀第 34 章，依照其中的學習順序，每個 Lab 之前讀完它的先備章節，再動手做。附錄 D 針對不同背景與目標，整理了更細的讀書路線與時程。

不管用哪一種讀法，第 1、2 章都建議先讀：第 1 章建立全書的地圖，第 2 章補齊後面每一章都會用到的 C、Linux 與除錯器基本功。

## 執行環境

書中的 C 程式都是標準 C（C17）加上 POSIX，在 **macOS arm64**（Apple Silicon）與 **Linux x86-64** 上都能編譯執行。每段「動手做」的輸出都是實際執行得到的，並註明執行環境。少數只能在 Linux 上執行的程式（例如使用 `epoll`、`/proc`）會在第一行標明 `// linux-only`；Linux 專屬工具（例如 `perf`、`strace`）的終端機輸出若不是實際執行得到，會標明「示意輸出」。

**組合語言一律以 x86-64 為準**，使用 AT&T 語法，並由編譯器實際產生，不是手寫的。即使你用的是 Apple Silicon 的 Mac，也可以用下面的指令產生和書中相同格式的 x86-64 組合語言：

```bash
clang -target x86_64-linux-gnu -O1 -S -fno-asynchronous-unwind-tables -o - file.c
```

第 7 章會附上 ARM64 的簡短對照。需要實際執行 x86-64 程式的場合（例如用 `gdb` 單步執行組合語言、做 CS:APP 的 Bomb Lab 與 Attack Lab），建議準備一台 Linux x86-64 的虛擬機或雲端機器，第 34 章比較了幾種作法的優缺點。

準備好了，就從第 1 章的 Hello World 開始。
