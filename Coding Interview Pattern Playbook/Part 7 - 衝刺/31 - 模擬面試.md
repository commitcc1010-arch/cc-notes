## 31.1 怎麼使用這六場模擬面試

這一章不是拿來「讀」的，而是拿來「考」的。每一場都設計成一輪 45 分鐘、兩道題的 coding interview：題 A 是本書出現過的題目，用來檢查你的核心題熟練度；題 B 是書中某道題的新變形，用來檢查你能不能把 pattern 搬到沒看過的題目上。兩題刻意選自不同 pattern，因為真實面試中第二題通常和第一題無關，切換思考模式本身就是考驗的一部分。

布置方式越接近真實越好。建議遵守下面幾條規則：

- **只看題目**。每場先讀「計時建議」與兩道題的題目敘述，就把後面的參考思路、追問與評分重點蓋住。題 A 只看標題中的書中題號，標題下方那兩段是思路摘要與評分提示，要和題 B 的參考思路一起蓋住；請先自己回想題目，想不起來再回原章看「題目」小節，但不要看解法。
- **計時並出聲**。用計時器，從讀題開始算 45 分鐘；全程把思考說出來，最好錄音。第 2 章 2.4 節說過，沉默是最常見的扣分來源，而自己練習時最容易養成沉默的習慣。
- **不執行程式**。先在純文字編輯器或紙上寫完，用手動追蹤驗證；時間到之後，才把程式貼到 Python 執行，對照參考解的測試。
- **找人當面試官更好**。如果有練習夥伴，把本節之後的內容交給對方，請他照「面試官可能的追問」提問，並用「評分重點」打分。
- **做完才看答案**。時間到就停筆，先填「自我檢討表」，再讀參考思路。檢討表裡答「否」的項目，就是下一次練習的重點。

六場的安排由淺入深，建議在讀完全書之後、面試前一到兩週開始，每隔一到兩天做一場，不要一天連做兩場，因為疲勞會讓結果失真。

### 評分方式

每場結束後，用下面四個維度替自己打分，每個維度 1–4 分。這四個維度與第 2 章 2.8 節相同；分數級距是本書為了自我檢討設計的對照尺度，不是任何公司的官方評分表，但它反映了公開面經中對 L5 等級的普遍期待：在時間內寫出最佳解、主動驗證、說得出取捨，而且由你推著解題前進。

| 分數 | Problem solving | Coding | Verification | Communication |
|---|---|---|---|---|
| 4 | 不需提示就推到最佳解，說得出關鍵觀察，follow-up 也能給具體做法 | 一次寫對，結構清楚，邊界自然融入 | 主動追蹤範例與邊界，自己找到並修正 bug | 全程說出意圖與決策，關鍵節點主動確認 |
| 3 | 需要一個小提示，或最佳解推得慢但正確 | 有一兩個小 bug，自己修正 | 有追蹤範例，但漏了一個邊界 | 大致清楚，偶有沉默 |
| 2 | 需要多次提示才到最佳解，或只寫出次佳解 | bug 由面試官指出，或程式結構凌亂 | 只說「應該對了」，沒有實際追蹤 | 常常沉默，或說很多但沒有資訊 |
| 1 | 沒有可行解 | 沒寫完 | 沒有驗證 | 無法讓面試官跟上 |

以 L5 為目標時，一場的合理期待是四個維度都至少 3 分，而且 problem solving 與 coding 至少一項 4 分。任何一個維度出現 2 分以下，就代表這個維度是你目前的短板，比分數總和更值得注意。

### 自我檢討表怎麼填

每場的自我檢討表有兩部分：共通項目與該場特有的項目。共通項目每場都一樣，用來追蹤習慣是否穩定；特有項目對應那兩題最容易出錯的地方。每一項只答「是」或「否」，並在備註寫下具體發生了什麼，例如「題 B 第 18 分鐘才發現窗口長度固定」。六場做完後，把所有「否」集中起來看，重複出現的項目就是你考前最後一週要針對練習的內容。

## 31.2 第一場：Hashing 與 Sliding Window

### 計時建議

第一場是熱身，兩題都是 Medium，重點是把節奏跑順。題 A 是標準核心題，應該在 15 分鐘內完成；題 B 需要從一道熟悉的題目推出新的維護方式，留給它多一點時間。

```text
 0 ─ 2 分   開場
 2 ─ 17 分  題 A：釐清 2、設計 3、寫程式 6、驗證 3、複雜度 1
17 ─ 40 分  題 B：釐清 3、設計 6、寫程式 8、驗證 4、複雜度 2
40 ─ 45 分  追問與你的提問
```

### 題 A：第 4 章核心題 3（128. Longest Consecutive Sequence）

給一個未排序的整數陣列，回傳最長的「數值連續」序列長度（元素在陣列中的位置不必相鄰），要求 O(n) 時間。這題你應該能在 2 分鐘內說完思路：把所有數放進 set，只從「x − 1 不在 set 裡」的 x 開始往上數，因為只有序列的起點會啟動內層迴圈，每個數最多被內層迴圈走到一次，所以總共 O(n)。

這題的評分重點不在演算法，而在你能不能說清楚「為什麼內層 while 迴圈不會讓它變成 O(n²)」。很多候選人寫對了程式，卻在面試官問「這不是兩層迴圈嗎」時答不出 amortized 的理由。另一個要主動提的邊界是重複元素：`[1, 2, 2, 3]` 的答案是 3，用 set 去重後自然處理。

### 題 B（新變形）：近似 anagram 的起點

這題改自第 6 章核心題 5（438. Find All Anagrams in a String）。

**題目**：給兩個只含小寫英文字母的字串 `s` 與 `p`，以及非負整數 `k`。令 `m = len(p)`。對每個起點 `i`，考慮長度為 `m` 的子字串 `s[i:i+m]`：如果最多把其中 `k` 個字元替換成任意字母，就能讓它成為 `p` 的一個 anagram（字母重排），就把 `i` 放進答案。依遞增順序回傳所有這樣的起點。`1 ≤ len(p)`，`len(s)` 最多 10⁵；如果 `len(p) > len(s)` 回傳空陣列。

- 範例 1：`s = "cbaebabacd"`、`p = "abc"`、`k = 0`，答案 `[0, 6]`，這就是原題。
- 範例 2：同上但 `k = 1`，答案 `[0, 1, 2, 3, 4, 5, 6, 7]`。例如起點 1 的 `"bae"` 把 `e` 換成 `c` 就是 `"bac"`。
- 範例 3：`s = "aaaa"`、`p = "ab"`、`k = 1`，答案 `[0, 1, 2]`；若 `k = 0` 則答案是空陣列。

**參考思路**：暴力解對每個窗口重新計數，再算需要替換幾個字元，O(n·m)。關鍵是先把「最少要替換幾個字元」這個量想清楚：窗口與 `p` 的字母多重集合中，能「對上」的字元數是 `overlap = Σ min(窗口中 c 的次數, p 中 c 的次數)`；對不上的 `m − overlap` 個字元每個都至少要換一次，而且換這麼多次就夠了（把多出來的字元換成缺少的字母），所以最少替換數就是 `m − overlap`。

窗口長度固定，每次右邊進一個字元、左邊出一個字元。`overlap` 可以 O(1) 更新：加入字元 `c` 之前，如果窗口中 `c` 的次數還小於 `p` 的需求，`overlap` 加一；移除 `c` 之後，如果次數掉到需求以下，`overlap` 減一。原題的「是否為 anagram」只是 `overlap == m` 的特例，所以這個變形本質上是把布林判斷換成一個可以增量維護的計數。

```text
s = "cbaebabacd"，p = "abc"（需求 a:1 b:1 c:1），k = 1，m = 3

窗口     起點  overlap  需替換 m-overlap  ≤ k？
cba      0     3        0                是
bae      1     2        1                是   e 進來時 e 的需求是 0，overlap 不變
aeb      2     2        1                是
eba      3     2        1                是
bab      4     2        1                是   第二個 b 超過需求，不計入 overlap
aba      5     2        1                是
bac      6     3        0                是
acd      7     2        1                是
```

**參考解法**：

```python
import random
from collections import Counter


def near_anagram_starts(s: str, p: str, k: int) -> list[int]:
    """回傳所有起點 i：s[i:i+m] 最多改 k 個字元就能成為 p 的 anagram。"""
    m = len(p)
    if m == 0 or m > len(s):
        return []
    need = Counter(p)
    have: Counter[str] = Counter()
    overlap = 0                      # sum(min(have[c], need[c]))
    result = []
    for right, ch in enumerate(s):
        if have[ch] < need[ch]:
            overlap += 1
        have[ch] += 1
        left = right - m + 1
        if left < 0:
            continue
        if m - overlap <= k:         # 需要修改的字元數
            result.append(left)
        out = s[left]
        have[out] -= 1
        if have[out] < need[out]:
            overlap -= 1
    return result


def near_anagram_brute(s: str, p: str, k: int) -> list[int]:
    m = len(p)
    if m == 0 or m > len(s):
        return []
    need = Counter(p)
    res = []
    for i in range(len(s) - m + 1):
        win = Counter(s[i:i + m])
        common = sum(min(win[c], need[c]) for c in win)
        if m - common <= k:
            res.append(i)
    return res


assert near_anagram_starts("cbaebabacd", "abc", 0) == [0, 6]
assert near_anagram_starts("cbaebabacd", "abc", 1) == [0, 1, 2, 3, 4, 5, 6, 7]
assert near_anagram_starts("aaaa", "ab", 0) == []
assert near_anagram_starts("aaaa", "ab", 1) == [0, 1, 2]
assert near_anagram_starts("ab", "abc", 3) == []
rng = random.Random(31)
for _ in range(2000):
    s = "".join(rng.choice("abc") for _ in range(rng.randint(0, 10)))
    p = "".join(rng.choice("abc") for _ in range(rng.randint(1, 4)))
    k = rng.randint(0, 3)
    assert near_anagram_starts(s, p, k) == near_anagram_brute(s, p, k), (s, p, k)
print("all tests passed")
```

時間 O(n + m)，每個字元進出窗口各一次、每次 O(1)；空間 O(Σ)，Σ 是字母表大小，這裡是 26。

### 面試官可能的追問

- **題 A：如果數字是一個一個串流進來，每來一個就要回報目前的最長長度？** 用 hash map 只在「區段端點」記錄區段長度：插入 x（若已存在就略過）時取 `left = len[x-1]`、`right = len[x+1]`，新長度 `left + right + 1`，只更新 `len[x]`、`len[x-left]`、`len[x+right]` 三個位置，並更新全域最大值。每次 O(1)；也可以用第 17 章的 union-find，攤銷近乎 O(1)。
- **題 A：如果要求 O(1) 額外空間？** 只能原地排序後一次掃描，跳過相等的相鄰元素、遇到差 1 就延長，O(n log n) 時間。要主動說明這是用時間換空間；面試中不必證明 O(n) 時間與 O(1) 額外空間能否兼得，說清楚取捨即可。
- **題 B：如果 k ≥ m？** 每個窗口都合法，答案就是 `0` 到 `len(s) − m` 的全部起點，可以直接回傳 `list(range(len(s) - m + 1))`。主動提到這個捷徑，代表你有檢查參數的極端值。
- **題 B：如果改成回傳「需要替換次數最少」的那些起點？** 掃描時同時維護目前的最小替換數與對應起點清單，遇到更小的就清空重來，仍是 O(n)。
- **題 B：如果不限制窗口長度，而是要找包含 p 所有字母（含次數）的最短子字串？** 窗口長度不再固定，變成可伸縮窗口：右指標擴張直到 `overlap == m`，再收縮左指標，就是第 6 章難題 1（76. Minimum Window Substring）。這個追問在檢查你能否分辨固定窗口與可變窗口。
- **題 B：如果 s 是串流，p 很長？** 演算法本身就是單趟掃描，只需要額外保留最近 m 個字元（用 deque）以便移出窗口，空間 O(m + Σ)。

### 評分重點

| 維度 | 這一場的 L5 表現 |
|---|---|
| Problem solving | 題 A 直接說出「只從起點開始數」並解釋 amortized O(n)；題 B 自己推出最少替換數 = `m − overlap`，並說明為什麼這個下限可以達到 |
| Coding | 題 B 的進出窗口更新順序正確（加入前判斷、移除後判斷），沒有 off-by-one；窗口未滿時不記錄答案 |
| Verification | 題 B 至少追蹤一個含重複字母的窗口（例如 `"bab"`），確認多出來的字母不會被算進 `overlap` |
| Communication | 一開始就點出題 B 是原題的推廣，讓面試官知道你的切入點；題 A 主動解釋兩層迴圈的複雜度 |

## 31.3 第二場：Binary Search 與 Heap

### 計時建議

題 A 是對答案做 binary search 的標準題，熟練的話 12–15 分鐘；題 B 需要同時維護兩個 heap，程式稍長，驗證時要特別小心「同時有多間空閒會議室」的情況。

```text
 0 ─ 2 分   開場
 2 ─ 17 分  題 A：釐清 2、設計 3、寫程式 5、驗證 4、複雜度 1
17 ─ 41 分  題 B：釐清 3、設計 6、寫程式 9、驗證 5、複雜度 1
41 ─ 45 分  追問與你的提問
```

### 題 A：第 8 章核心題 4（875. Koko Eating Bananas）

有 n 堆香蕉，每小時只能吃一堆中的最多 k 根，一堆吃完那小時就結束；要在 h 小時內吃完，求最小的整數速度 k。思路是 binary search on answer（對答案二分）：速度越快，所需時數越少，判定「速度 k 能否在 h 小時內吃完」對 k 單調，所以在 `[1, max(piles)]` 中找第一個可行的 k。每次判定是 `Σ ceil(p / k)`，總時間 O(n log max(piles))。

這題的評分重點是二分的邊界寫法與上下界的理由：下界是 1、上界是 `max(piles)`（速度再快也是每堆至少一小時），以及用 `(p + k - 1) // k` 做整數向上取整，避免浮點誤差。面試官常常會要求你說出迴圈結束時 `lo` 為什麼一定是答案，請用第 8 章的 invariant 說法：「`lo` 左邊都不可行、`hi` 以及右邊都可行」。

### 題 B（新變形）：會議室編號分配

這題改自第 9 章核心題 5（253. Meeting Rooms II）。

**題目**：給 n 場會議 `meetings[i] = [start, end]`，代表半開區間 `[start, end)`，`start < end`。會議室有無限多間，編號 0、1、2、…。依開始時間由早到晚處理會議（開始時間相同時，輸入中較前面的先處理），每場會議分配給「此刻空閒中編號最小」的會議室；所謂空閒，是指該會議室上一場會議的結束時間 ≤ 這場的開始時間。回傳兩個東西：依輸入順序每場會議分配到的會議室編號，以及總共用到幾間會議室。n 最多 10⁵。

- 範例 1：`[[0, 30], [5, 10], [15, 20]]` → `([0, 1, 1], 2)`。第三場開始時會議室 1 已在 10 空出。
- 範例 2：`[[0, 10], [1, 5], [2, 3], [11, 12]]` → `([0, 1, 2, 0], 3)`。時間 11 時三間都空著，最早空出的是 2，但要拿編號最小的 0。
- 範例 3：空陣列 → `([], 0)`。

**參考思路**：原題只要數量，可以只用一個存結束時間的 min-heap。這題要編號，就必須分開「誰最早空出」與「空閒中誰編號最小」兩個問題，因為範例 2 顯示這兩個順序不同。暴力解對每場會議掃過所有會議室找編號最小的空閒者，O(n·R)，R 是會議室數，最壞 O(n²)。

改進是兩個 heap：`busy` 以 `(結束時間, 編號)` 排序，處理每場會議前，把所有結束時間 ≤ 開始時間的會議室彈出，放進以編號排序的 `free` heap；接著如果 `free` 不空就取最小編號，否則開一間新的會議室。每間會議室每次被占用只會進出兩個 heap 各一次，所以總時間 O(n log n)。用到的會議室總數恰好等於原題的答案，因為只有在沒有空閒會議室時才開新房間。

```text
meetings = [[0,10], [1,5], [2,3], [11,12]]（已依開始時間排序）

處理      先釋放（end ≤ start）  free     分配   busy（end, room）
[0,10]    無                     []       新 0   (10,0)
[1,5]     無                     []       新 1   (5,1) (10,0)
[2,3]     無                     []       新 2   (3,2) (5,1) (10,0)
[11,12]   (3,2) (5,1) (10,0)     [0,1,2]  取 0   (12,0)

如果只用「最早空出」的那間，第四場會拿到 2，答案錯誤。
```

**參考解法**：

```python
import heapq
import random


def assign_rooms(meetings: list[list[int]]) -> tuple[list[int], int]:
    """每場會議 [start, end) 依開始時間分配到目前空閒中編號最小的會議室。

    回傳 (每場會議的會議室編號，依輸入順序), 用到的會議室總數。
    """
    order = sorted(range(len(meetings)), key=lambda i: (meetings[i][0], i))
    busy: list[tuple[int, int]] = []   # (結束時間, 會議室編號)
    free: list[int] = []               # 空閒會議室編號（min-heap）
    next_room = 0
    room_of = [0] * len(meetings)
    for i in order:
        start, end = meetings[i]
        while busy and busy[0][0] <= start:      # 釋放已結束的會議室
            heapq.heappush(free, heapq.heappop(busy)[1])
        if free:
            room = heapq.heappop(free)
        else:
            room = next_room
            next_room += 1
        room_of[i] = room
        heapq.heappush(busy, (end, room))
    return room_of, next_room


def assign_rooms_brute(meetings):
    order = sorted(range(len(meetings)), key=lambda i: (meetings[i][0], i))
    room_end: list[int] = []
    room_of = [0] * len(meetings)
    for i in order:
        start, end = meetings[i]
        for r, e in enumerate(room_end):
            if e <= start:
                room_end[r] = end
                room_of[i] = r
                break
        else:
            room_of[i] = len(room_end)
            room_end.append(end)
    return room_of, len(room_end)


assert assign_rooms([[0, 30], [5, 10], [15, 20]]) == ([0, 1, 1], 2)
assert assign_rooms([[1, 5], [2, 6], [5, 7], [6, 8]]) == ([0, 1, 0, 1], 2)
assert assign_rooms([[3, 4], [1, 2]]) == ([0, 0], 1)
assert assign_rooms([]) == ([], 0)
assert assign_rooms([[0, 10], [1, 5], [2, 3], [11, 12]]) == ([0, 1, 2, 0], 3)
rng = random.Random(7)
for _ in range(2000):
    ms = []
    for _ in range(rng.randint(0, 8)):
        s = rng.randint(0, 10)
        ms.append([s, s + rng.randint(1, 5)])
    assert assign_rooms(ms) == assign_rooms_brute(ms), ms
print("all tests passed")
```

時間 O(n log n)：排序一次，每場會議在兩個 heap 中各最多進出一次。空間 O(n)。

### 面試官可能的追問

- **題 A：如果 h 可能小於堆數？** 那麼不論速度多快都做不到，因為每堆至少要一小時，應該在開頭回傳 -1 或丟出例外。這也說明了上界 `max(piles)` 的意義：速度超過它不會再減少時數。
- **題 A：判定函式能否更快？** 若同一組 piles 要回答很多不同的 h，可以先排序並建 prefix sum，但每次判定仍需對每堆向上取整，一般不值得；更實際的優化是把下界改成 `ceil(sum / h)`，縮小搜尋範圍。這題 O(n log V) 已是面試期待的答案。
- **題 B：如果會議室只有 n 間，沒有空閒時會議要延後到最早空出的那間，並保持原本長度？** 這是 2402. Meeting Rooms III 的設定。`free` 初始放入 0..n−1；沒有空閒時從 `busy` 彈出最早結束的 `(end, room)`，這場會議改成 `[end, end + 長度)`。因為 `busy` 的 tuple 先比結束時間再比編號，同時結束時自然選到編號小的。設 m 是會議數，排序 O(m log m)，之後每場 O(log n)。
- **題 B：如果會議是線上一場一場到達，且保證依開始時間遞增？** 演算法本身就是線上的，每場 O(log n)，不需要事先排序。若到達順序不保證遞增，就無法在到達時立刻決定，需要先緩衝或改變規則。
- **題 B：如果只要回答「同一時間最多幾場會議」，能否不用 heap？** 可以用第 9 章的 sweep line：把開始與結束時間分別排序，雙指標掃描，遇到 `end ≤ start` 時先處理結束，O(n log n)、不需要 heap，但無法給出編號。
- **題 B：如何驗證你的實作？** 主動提出用暴力解（逐間掃描找最小空閒編號）做隨機對拍，值域刻意很小，製造大量同時開始、同時結束的案例。這正是參考解法的測試方式。

| Coding | 題 A 二分迴圈邊界一致（`lo < hi` 搭配 `hi = mid`）；題 B 釋放條件寫 `<=`，符合半開區間 |

### 題 A：第 12 章核心題 5（236. Lowest Common Ancestor of a Binary Tree）

給一棵二元樹與樹中兩個節點 p、q，回傳它們最低的共同祖先（節點可以是自己的祖先）。思路是後序 DFS：每個子樹回傳「在這棵子樹中找到的 p 或 q，或已經找到的 LCA」；如果左右子樹都回傳非空，目前節點就是 LCA；如果目前節點本身是 p 或 q，直接回傳它。O(n) 時間、O(h) 遞迴空間。

評分重點是你能不能清楚說出遞迴函式的回傳值語意。這題的程式只有七八行，但如果說不清楚「回傳值代表什麼」，面試官會懷疑你是背的。另一個要主動說的前提是「題目保證 p、q 都在樹中」，因為這個保證讓「遇到 p 就直接回傳、不必往下找 q」是正確的：如果 q 在 p 的子樹裡，答案本來就是 p。

### 題 B（新變形）：錯開時間的腐爛橘子

這題改自第 15 章核心題 3（994. Rotting Oranges）。

**題目**：給一個 R × C 的格子 `grid`，`0` 是空格、`1` 是橘子。另給一個清單 `sources`，每個元素 `(r, c, t)` 表示格子 `(r, c)` 上的橘子會在時間 `t` 自己開始腐爛（若它在 `t` 之前已被傳染，就以較早的時間為準；若該格是空格則忽略）。腐爛的橘子在下一分鐘會傳染上下左右相鄰的橘子。回傳所有橘子都腐爛的最早時間；若有橘子永遠不會腐爛，回傳 -1；若沒有任何橘子，回傳 0。R·C 最多 10⁵，`t` 可以到 10⁹，來源數 S 最多 10⁵。

- 範例 1：`grid = [[1, 1, 1, 1, 1]]`、`sources = [(0, 0, 0), (0, 4, 1)]`，答案 2。左邊的波在時間 0 出發，右邊的在時間 1 出發，兩波在中間相遇，最後一顆在時間 2 腐爛。
- 範例 2：同樣的格子，`sources = [(0, 0, 0), (0, 4, 9)]`，答案 4。右邊的來源還沒啟動，整排就已經被左邊的波傳染完了。
- 範例 3：`grid = [[1, 0, 1]]`、`sources = [(0, 0, 0)]`，答案 -1。

**參考思路**：每格的腐爛時間是 `min over 來源 (t_i + 從來源走到這格的步數)`。暴力解對每個來源各跑一次 BFS，O(S·R·C)，太慢。原題所有來源都在時間 0 出發，所以把它們一起放進 queue 做 multi-source BFS；這題的來源出發時間不同，不能一開始全部放進去，否則晚出發的來源會「提早」傳染。

觀察是：BFS 一層代表一分鐘，只要在處理時間 `cur` 這一層之前，把所有 `t == cur` 的來源加進這一層，就等於讓它們在正確的時間加入擴散。所以先把來源依 `t` 排序，用指標依序注入。當目前沒有正在擴散的波時，直接把 `cur` 跳到下一個來源的 `t`，這樣即使 `t` 到 10⁹ 也不會空轉。每格只會被設定一次時間，因為 BFS 逐層前進時，先被設定的時間一定最小，這與一般 BFS 的正確性理由相同。另一種做法是把每個來源以初始距離 `t_i` 放進 Dijkstra，O(RC log RC)，也可以接受，但這裡的分層注入是 O(RC + S log S)。

```text
grid = [[1,1,1,1,1]]，sources = [(0,0,0), (0,4,1)]

cur   注入來源       這一層 frontier     設定時間後的列
0     (0,0)          [(0,0)]             0 . . . .
1     (0,4)          [(0,1), (0,4)]      0 1 . . 1
2     無             [(0,2), (0,3)]      0 1 2 2 1
3     無             []                  結束，最大值 2

若一開始就把 (0,4) 放進時間 0 的 queue，(0,3) 會被算成 1，答案錯成 1。
```

**參考解法**：

```python
import random
from collections import deque


def all_rotten_time(grid: list[list[int]], sources: list[tuple[int, int, int]]) -> int:
    """grid：0 空格、1 橘子。sources：(r, c, t) 表示該格橘子在時間 t 自行開始腐爛。
    每分鐘腐爛橘子會傳染上下左右的橘子。回傳全部腐爛的最早時間，做不到回傳 -1。"""
    rows, cols = len(grid), len(grid[0]) if grid else 0
    srcs = sorted((t, r, c) for r, c, t in sources if grid[r][c] == 1)
    rot: dict[tuple[int, int], int] = {}
    frontier: list[tuple[int, int]] = []
    i, cur = 0, 0
    while frontier or i < len(srcs):
        if not frontier:                     # 沒有正在擴散的波，直接跳到下一個來源的時間
            cur = srcs[i][0]
        while i < len(srcs) and srcs[i][0] == cur:
            _, r, c = srcs[i]
            i += 1
            if (r, c) not in rot:            # 已經被更早的波感染就略過
                rot[(r, c)] = cur
                frontier.append((r, c))
        nxt = []
        for r, c in frontier:
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1 and (nr, nc) not in rot:
                    rot[(nr, nc)] = cur + 1
                    nxt.append((nr, nc))
        frontier = nxt
        cur += 1
    total = sum(row.count(1) for row in grid)
    if len(rot) < total:
        return -1
    return max(rot.values(), default=0)


def all_rotten_brute(grid, sources):
    rows, cols = len(grid), len(grid[0]) if grid else 0
    best = {}
    for r0, c0, t0 in sources:
        if grid[r0][c0] != 1:
            continue
        dist = {(r0, c0): 0}
        q = deque([(r0, c0)])
        while q:
            r, c = q.popleft()
            for nr, nc in ((r + 1, c), (r - 1, c), (r, c + 1), (r, c - 1)):
                if 0 <= nr < rows and 0 <= nc < cols and grid[nr][nc] == 1 and (nr, nc) not in dist:
                    dist[(nr, nc)] = dist[(r, c)] + 1
                    q.append((nr, nc))
        for cell, d in dist.items():
            best[cell] = min(best.get(cell, 10**9), t0 + d)
    total = sum(row.count(1) for row in grid)
    if len(best) < total:
        return -1
    return max(best.values(), default=0)


g = [[1, 1, 1, 1, 1]]
assert all_rotten_time(g, [(0, 0, 0)]) == 4
assert all_rotten_time(g, [(0, 0, 0), (0, 4, 1)]) == 2      # 兩波在中間相遇
assert all_rotten_time(g, [(0, 0, 0), (0, 4, 9)]) == 4      # 晚到的來源沒有幫助
assert all_rotten_time([[1, 0, 1]], [(0, 0, 0)]) == -1      # 被空格隔開
assert all_rotten_time([[0, 0]], []) == 0                   # 沒有橘子
rng = random.Random(3)
for _ in range(1500):
    R, C = rng.randint(1, 4), rng.randint(1, 4)
    grid = [[1 if rng.random() < 0.75 else 0 for _ in range(C)] for _ in range(R)]
    srcs = [(rng.randrange(R), rng.randrange(C), rng.randint(0, 6)) for _ in range(rng.randint(0, 3))]
    assert all_rotten_time(grid, srcs) == all_rotten_brute(grid, srcs), (grid, srcs)
print("all tests passed")
```

時間 O(R·C + S log S)：每格最多被設定一次、每個來源被排序與注入一次；`cur` 的跳躍讓時間不受 `t` 的數值大小影響。空間 O(R·C + S)。

### 面試官可能的追問

- **題 A：如果 p 或 q 可能不在樹中？** 「遇到 p 就回傳」的捷徑不再成立，因為無法確定 q 存在。改成完整走完整棵樹，同時計算找到了幾個目標，只有兩個都找到才回傳 LCA，否則回傳 None。仍是 O(n)。
- **題 A：如果每個節點有 parent 指標，但沒有 root？** 問題變成兩條往上走的 linked list 找交點：先算兩者深度，深的先往上走差距步數，再一起往上直到相遇，O(h) 時間、O(1) 空間；也可以用第 11 章「走完自己的路再走對方的路」的雙指標技巧。
- **題 A：如果是 BST？** 可以利用值的大小：兩者都小於目前節點就往左、都大於就往右，否則目前節點就是答案，O(h) 時間、迭代寫法 O(1) 空間。
- **題 B：如果傳染到不同格子需要不同時間（每格有自己的傳染延遲）？** 邊權不再一致，BFS 的「一層一分鐘」失效，要改成 multi-source Dijkstra：每個來源以初始距離 `t_i` 放進 heap，O(RC log RC)。這是第 18 章的內容，追問在檢查你是否知道 BFS 只適用於等權。
- **題 B：如果要回報每顆橘子是被哪一個來源傳染的？** 在 frontier 中同時帶著來源編號，設定時間時一併記錄。若兩波同時到達需要規則（例如編號小者優先），就在注入與擴展時依該規則排序同一層的處理順序。
- **題 B：如果 sources 很少但格子極大，而且只問某一格的腐爛時間？** 可以從那一格反向做一次 BFS，遇到每個來源時計算 `t_i + 距離`，但要走到所有可達來源才能確定最小值；若格子沒有空格，距離就是曼哈頓距離，直接 O(S) 計算。

### 評分重點

| 維度 | 這一場的 L5 表現 |
|---|---|
| Problem solving | 題 B 先寫出「每格時間 = min(t_i + 距離)」的定義，再指出原題一次放入所有來源的做法為什麼錯，並找到分層注入或 Dijkstra 的修正 |
| Coding | 題 B 處理「沒有正在擴散的波時跳到下一個來源時間」，以及「來源格已被更早傳染」兩個細節 |
| Verification | 題 B 至少追蹤一個「晚到來源完全沒幫助」與一個「被隔開」的案例；題 A 測 p 是 q 祖先的情況 |
| Communication | 題 A 清楚說出遞迴回傳值的語意；題 B 主動比較分層注入與 Dijkstra 的複雜度 |

## 31.5 第四場：Backtracking 與 DP

這一場刻意把「列出所有解」與「求最佳解」放在一起：題 A 要枚舉，題 B 只要一個最佳解。兩題的切換本身就是考點，面試官常常會在追問中把兩者對調。


### 題 A：第 19 章核心題 3（39. Combination Sum）

給一組互不相同的正整數 `candidates` 與目標 `target`，回傳所有和為 `target` 的組合，每個數可以重複使用，組合內的順序不重要（`[2, 2, 3]` 與 `[3, 2, 2]` 算同一個）。思路是 backtracking（回溯）：遞迴參數帶一個起始索引 `start`，每層只從 `start` 往後選，選了 `candidates[i]` 之後遞迴時仍傳 `i`（可以重複使用），這樣產生的組合天然是非遞減的，不會重複。先排序後，遇到 `candidates[i] > remaining` 就可以直接 `break`。

評分重點是去重的方式：用 `start` 控制「只往後選」才是正確的設計，先產生所有排列再用 set 去重會被視為 problem solving 不足。複雜度沒有簡單的封閉式，合理的說法是「與輸出大小成正比，再乘上每個組合複製的長度；最壞情況是指數級：遞迴深度最多 T/m，每層最多 n 個分支，所以節點數的上界約為 O(n^(T/m + 1))，T 是 target、m 是最小的候選值」。

### 題 B（新變形）：最少字數的切分

這題改自第 21 章核心題 4（139. Word Break）。

**題目**：給字串 `s` 與一個字典 `words`（字串清單，字可以重複使用）。把 `s` 切成若干段，每段都必須是字典中的字，並且讓段數最少。回傳一種段數最少的切法（字串清單）；如果無法切分，回傳空清單。`s` 長度最多 1000，字典最多 1000 個字、每個字長度最多 20。為了簡化，假設 `s` 不為空時才有意義；`s` 為空時回傳空清單。

- 範例 1：`s = "catsanddog"`、`words = ["cat", "cats", "and", "sand", "dog"]`，答案是三個字，例如 `["cats", "and", "dog"]` 或 `["cat", "sand", "dog"]`，兩者都可以。
- 範例 2：`s = "aaaa"`、`words = ["a", "aa", "aaa"]`，最少兩個字，例如 `["a", "aaa"]` 或 `["aa", "aa"]`。
- 範例 3：`s = "catsandog"`、同一個字典，無法切分，回傳 `[]`。

**參考思路**：暴力解是 backtracking 枚舉所有切法，再取最短，最壞是指數級（例如全是 `a`、字典有 `a`、`aa`、`aaa` 時）。觀察是：「從位置 i 開始切到結尾的最少字數」只和 i 有關，與前面怎麼切無關，所以有重疊子問題，可以 DP。原題的 `dp[i]` 是布林值「`s[:i]` 能否切分」，這題把它換成整數「`s[:i]` 最少切成幾個字」，轉移是 `best[i] = min(best[j] + 1)`，其中 `s[j:i]` 在字典中。

要回傳切法而不只是字數，就額外記 `prev[i]`：達到最小值時最後一個字的起點 j。最後從 `n` 沿著 `prev` 往回走，就能還原出整個切法。內層迴圈只需要看 `i − max_len` 到 `i − 1` 的 j，因為更長的片段不可能在字典中。另一個等價的看法是把位置 0..n 當作節點、字典字當作邊，求從 0 到 n 的最少邊數，也就是一次 BFS（第 15 章）。

```text
s = "aaaa"，words = {a, aa, aaa}，max_len = 3

i     候選 j（s[j:i] 在字典中）        best[i]   prev[i]
0     —                                 0         —
1     j=0 "a"                           1         0
2     j=0 "aa"→1、j=1 "a"→2             1         0
3     j=0 "aaa"→1、j=1、j=2             1         0
4     j=1 "aaa"→2、j=2 "aa"→2、j=3 "a"→2  2         1   （第一個達到最小值的 j）

還原：4 → prev 1，片段 "aaa"；1 → prev 0，片段 "a"；答案 ["a", "aaa"]
```

**參考解法**：

```python
import random


def min_word_break(s: str, words: list[str]) -> list[str]:
    """把 s 切成字典中的字，使用的字數最少；回傳那組字，無法切分回傳 []。"""
    vocab = set(words)
    max_len = max(map(len, vocab), default=0)
    n = len(s)
    INF = float("inf")
    best = [INF] * (n + 1)        # best[i]：切分 s[:i] 的最少字數
    prev = [-1] * (n + 1)         # prev[i]：最後一個字的起點
    best[0] = 0
    for i in range(1, n + 1):
        for j in range(max(0, i - max_len), i):
            if best[j] + 1 < best[i] and s[j:i] in vocab:
                best[i] = best[j] + 1
                prev[i] = j
    if best[n] == INF:
        return []
    out, i = [], n
    while i > 0:
        out.append(s[prev[i]:i])
        i = prev[i]
    return out[::-1]


def min_word_break_brute(s, words):
    vocab = set(words)
    best = None
    def go(i, path):
        nonlocal best
        if i == len(s):
            if best is None or len(path) < best:
                best = len(path)
            return
        for j in range(i + 1, len(s) + 1):
            if s[i:j] in vocab:
                go(j, path + [s[i:j]])
    go(0, [])
    return best


def valid(s, words, ans):
    return "".join(ans) == s and all(w in words for w in ans)


r = min_word_break("catsanddog", ["cat", "cats", "and", "sand", "dog"])
assert len(r) == 3 and valid("catsanddog", ["cat", "cats", "and", "sand", "dog"], r)
assert min_word_break("aaaa", ["a", "aa", "aaa"]) == ["a", "aaa"]
assert min_word_break("catsandog", ["cats", "dog", "sand", "and", "cat"]) == []
assert min_word_break("", ["a"]) == []    # 空字串：0 個字，回傳空清單
rng = random.Random(11)
for _ in range(1500):
    s = "".join(rng.choice("ab") for _ in range(rng.randint(1, 9)))
    words = list({"".join(rng.choice("ab") for _ in range(rng.randint(1, 3))) for _ in range(rng.randint(1, 4))})
    got = min_word_break(s, words)
    want = min_word_break_brute(s, words)
    if want is None:
        assert got == []
    else:
        assert len(got) == want and valid(s, words, got), (s, words, got)
print("all tests passed")
```

時間 O(n·L·L)：n 個位置、每個位置最多看 L 個起點（L 是最長字長），每次切片與雜湊是 O(L)。空間 O(n + 字典總長度)。注意 `best[j] + 1 < best[i]` 放在 `s[j:i] in vocab` 之前，可以先用便宜的整數比較略過不可能改善的 j。

### 面試官可能的追問

- **題 A：如果每個數最多用一次，且 candidates 有重複值？** 這是 40. Combination Sum II。排序後遞迴改傳 `i + 1`；在同一層中，如果 `candidates[i] == candidates[i - 1]` 且 `i > start` 就跳過，避免同一層選到相同的值而產生重複組合。
- **題 A：如果只要組合的數量？** 不需要枚舉，改成完全背包計數：`ways[0] = 1`，外層迴圈跑候選值、內層跑金額，`ways[x] += ways[x - c]`，O(n·T)，這就是第 23 章核心題 3（518. Coin Change II）。迴圈順序反過來會變成計算排列數，這個差異是常見的追問。
- **題 A：如果只要最少用幾個數？** 變成第 21 章核心題 2（322. Coin Change），`dp[x] = min(dp[x − c] + 1)`，O(n·T)。這三個追問合起來，是在檢查你能否分辨「列出全部、數有幾個、找最佳」三種問法分別對應 backtracking、計數 DP、最佳化 DP。
- **題 B：如果要回傳所有可行切法（不只最少的）？** 這是 140. Word Break II。用記憶化遞迴：`solve(i)` 回傳 `s[i:]` 的所有切法清單，並快取。要主動說明輸出本身可能是指數級，所以沒有多項式時間的保證；可以先用原題的布林 DP 剪掉不可能到達結尾的位置。
- **題 B：如果字典很大、字很長，切片成本太高？** 改用第 13 章核心題 4 的 Trie：從每個可到達的位置 j 往後沿 Trie 走，走到字尾節點就更新 `best[i]`，走不下去就停。每個位置的工作量受限於 Trie 中實際存在的前綴，避免建立大量切片。
- **題 B：如果每個字有不同的成本，要最小化總成本？** 轉移改成 `best[i] = min(best[j] + cost[s[j:i]])`，仍是 DAG 上的最短路，順序 DP 依然正確，複雜度不變。若成本可能為負也沒關係，因為位置只會往右走，圖沒有環。

### 題 A：第 16 章核心題 2（210. Course Schedule II）

有 n 門課，`prerequisites[i] = [a, b]` 表示修 a 之前必須先修 b；回傳一個可以修完所有課的順序，若不可能（有環）回傳空陣列。思路是 Kahn's algorithm：建圖 `b → a` 並計算每門課的入度，把入度為 0 的課放進 queue，每取出一門就把它的後繼入度減一，減到 0 就加入 queue。最後如果輸出長度小於 n，代表有環。O(V + E)。

評分重點是邊的方向與環的偵測。很多人把邊建反，結果拓撲順序正好顛倒；寫程式前用一個 `[[1, 0]]` 的小例子說出「0 要在 1 之前，所以邊是 0 → 1」，可以避免這個錯誤。另一個要主動說的是「為什麼輸出長度小於 n 就代表有環」：環上的每個節點入度永遠不會降到 0，所以永遠不會被輸出。

### 題 B（新變形）：有一張折價券的訊號延遲

這題改自第 18 章核心題 1（743. Network Delay Time）。

**題目**：有 n 個節點，編號 1 到 n。`times[i] = [u, v, w]` 是一條有向邊，訊號從 u 傳到 v 需要 w 單位時間（w ≥ 0 的整數）。訊號從節點 k 發出。每一條傳到某個節點的路徑，可以在其中至多一條邊上使用折價券，讓那條邊的時間變成 `w // 2`。每個節點的收到時間，是所有路徑中（每條路徑各自決定要不要、在哪裡用折價券）的最小值。回傳所有節點都收到訊號的最晚時間；若有節點收不到，回傳 -1。n 最多 100，邊數最多 6000。

- 範例 1：`times = [[1, 2, 10], [2, 3, 10]]`、`n = 3`、`k = 1`，答案 15。節點 3 的最佳路徑是在其中一條邊用折價券：5 + 10 = 15。
- 範例 2：`times = [[1, 2, 5], [2, 3, 5], [1, 3, 11]]`、`n = 3`、`k = 1`，答案 5。原本最短的 1→2→3（總長 10）用了折價券是 7；但直接邊 1→3（11）用折價券是 5，更好。
- 範例 3：`times = [[1, 2, 1]]`、`n = 2`、`k = 2`，節點 1 收不到，答案 -1。

**參考思路**：範例 2 正好推翻最直覺的做法：「先跑原本的 Dijkstra，再把最短路徑上最長的邊打折」。打折之後最好的路徑，未必是打折之前最短的路徑，所以不能先決定路徑再決定折價券。暴力解是對每條邊試一次「把它打折後跑 Dijkstra」，O(E · E log V)，在這個規模下約 6000 × 6000 × 7，太慢。

關鍵觀察是把「折價券用掉沒有」放進狀態：節點 `(v, used)`，`used ∈ {0, 1}`。從 `(u, 0)` 出發的每條邊有兩種走法：不用券到 `(v, 0)`，代價 w；用券到 `(v, 1)`，代價 `w // 2`。從 `(u, 1)` 出發只能不用券到 `(v, 1)`。這張分層圖的邊權都非負，所以直接在上面跑 Dijkstra，每個節點的答案是 `min(dist[v][0], dist[v][1])`。狀態數 2V、邊數 3E，複雜度仍是 O(E log V)。

```text
範例 2 的分層圖（括號內是代價）：

第 0 層（未用券）    1 ──(5)──▶ 2 ──(5)──▶ 3        1 ──(11)──▶ 3
                     │          │                    │
                    (2)        (2)                  (5)      ← 用券的跨層邊
                     ▼          ▼                    ▼
第 1 層（已用券）    2' ──(5)─▶ 3'                   3'

Dijkstra 由 (1,0) 出發：
pop (0, 1,0) → 推 (5, 2,0)、(2, 2,1)、(11, 3,0)、(5, 3,1)
pop (2, 2,1) → 3,1：2+5 = 7 不小於 dist[3][1] = 5，不更新
pop (5, 2,0) → 推 (10, 3,0)；用券到 3,1 是 5+2 = 7，不更新
pop (5, 3,1) → 節點 3 的答案 min(10, 5) = 5
```

**參考解法**：

```python
import heapq
import random


def delay_with_coupon(times: list[list[int]], n: int, k: int) -> int:
    """有向圖 times[i] = (u, v, w)，節點 1..n，訊號從 k 出發。
    每條訊號路徑最多可以把一條邊的時間打對折（w // 2）。回傳所有節點收到訊號的最晚時間，
    有節點收不到回傳 -1。"""
    graph: dict[int, list[tuple[int, int]]] = {u: [] for u in range(1, n + 1)}
    for u, v, w in times:
        graph[u].append((v, w))
    INF = float("inf")
    dist = [[INF, INF] for _ in range(n + 1)]   # dist[v][used]
    dist[k][0] = 0
    heap = [(0, k, 0)]
    while heap:
        d, u, used = heapq.heappop(heap)
        if d > dist[u][used]:
            continue                                  # 過期的 heap 項目
        for v, w in graph[u]:
            if d + w < dist[v][used]:                 # 不用折價券
                dist[v][used] = d + w
                heapq.heappush(heap, (d + w, v, used))
            if not used and d + w // 2 < dist[v][1]:  # 在這條邊用掉折價券
                dist[v][1] = d + w // 2
                heapq.heappush(heap, (d + w // 2, v, 1))
    ans = max(min(dist[v]) for v in range(1, n + 1))
    return -1 if ans == INF else ans


def dijkstra(edges, n, k):
    g = {u: [] for u in range(1, n + 1)}
    for u, v, w in edges:
        g[u].append((v, w))
    dist = {k: 0}
    h = [(0, k)]
    while h:
        d, u = heapq.heappop(h)
        if d > dist[u]:
            continue
        for v, w in g[u]:
            if d + w < dist.get(v, float("inf")):
                dist[v] = d + w
                heapq.heappush(h, (d + w, v))
    return dist


def delay_with_coupon_brute(times, n, k):
    best = dijkstra(times, n, k)
    for i in range(len(times)):
        mod = [list(e) for e in times]
        mod[i][2] //= 2
        for v, d in dijkstra(mod, n, k).items():
            best[v] = min(best.get(v, float("inf")), d)
    if len(best) < n:
        return -1
    return max(best.values())


assert delay_with_coupon([[1, 2, 10], [2, 3, 10]], 3, 1) == 15
assert delay_with_coupon([[1, 2, 5], [2, 3, 5], [1, 3, 11]], 3, 1) == 5   # 打折後換了路徑
assert delay_with_coupon([[2, 1, 1], [2, 3, 1], [3, 4, 1]], 4, 2) == 1
assert delay_with_coupon([[1, 2, 1]], 2, 2) == -1
assert delay_with_coupon([], 1, 1) == 0
rng = random.Random(5)
for _ in range(1500):
    n = rng.randint(1, 5)
    times = [[rng.randint(1, n), rng.randint(1, n), rng.randint(0, 9)] for _ in range(rng.randint(0, 8))]
    k = rng.randint(1, n)
    assert delay_with_coupon(times, n, k) == delay_with_coupon_brute(times, n, k), (times, n, k)
print("all tests passed")
```

時間 O(E log V)：狀態數 2V、每條原始邊最多產生三條分層邊。空間 O(V + E)。

### 面試官可能的追問

- **題 A：如果有多個合法順序，要回傳字典序最小的？** 把 queue 換成 min-heap，每次取出編號最小的入度 0 節點，O((V + E) log V)。要能說明為什麼這樣得到字典序最小：每一步都選了目前所有可選的課中最小的，而之後可選的集合不會因為這個選擇變差。
- **題 A：如果每學期可以修任意多門沒有依賴衝突的課，最少要幾個學期？** 把 Kahn's algorithm 改成逐層處理，層數就是答案；如果每門課有不同的修課時間，就是第 16 章難題 5（2050. Parallel Courses III），在拓撲序上算最長路徑。
- **題 A：如果要回報哪些課在環上？** Kahn's algorithm 結束後，入度仍大於 0 的節點是「在環上或依賴環」的課。若要精確找出環本身，改用 DFS 三色標記，遇到灰色節點時沿著遞迴堆疊回溯出環。
- **題 B：如果有 c 張折價券？** 狀態改成 `(v, used)`，`used ∈ [0, c]`，狀態數 (c + 1)V，複雜度 O(c · E log(cV))。這是同一個技巧的直接推廣，面試官多半在檢查你是否真的理解「把資源放進狀態」。
- **題 B：如果折價券改成「把一條邊變成 0」？** 只要把用券的代價從 `w // 2` 改成 0，演算法不變，邊權仍非負，Dijkstra 仍然正確。
- **題 B：如果限制最多經過 K 條邊？** 步數也變成狀態的一部分，這時常用第 18 章核心題 2（787. Cheapest Flights Within K Stops）的 Bellman-Ford 式 K 輪鬆弛，每輪用上一輪的距離複製，O(K · E)；若同時有折價券，每輪對兩層都做鬆弛即可。
- **題 B：如果邊權可能為負？** Dijkstra 不再正確，因為已經彈出的節點可能之後被更短的路徑更新。分層圖本身仍成立，改在分層圖上跑 Bellman-Ford，O(V · E)，並可順便偵測負環。

### 題 A：第 10 章難題 1（84. Largest Rectangle in Histogram）

給一個非負整數陣列代表柱狀圖每根柱子的高度（寬度都是 1），求圖中能畫出的最大矩形面積。思路是 monotonic stack：維護一個高度遞增的索引 stack；當目前柱子比 stack 頂端矮時，頂端那根柱子「向右能延伸的範圍」到此為止，而它向左能延伸到新的 stack 頂端之後，所以以它為高的最大矩形寬度是 `i − stack[-1] − 1`（stack 為空時是 `i`）。在陣列尾端補一根高度 0 的柱子，確保所有柱子最後都被彈出。每個索引 push、pop 各一次，O(n)。

評分重點是寬度公式的推導，而不是背出程式。建議先用「每根柱子作為矩形的最矮柱，左右各能延伸到哪裡」來定義問題，說出這等價於找左右兩側第一個更矮的柱子，再說明 stack 如何同時給出兩者。面試官很可能要你在 `[2, 1, 5, 6, 2, 3]` 上逐步追蹤 stack 內容，請事先練習到能流暢地說出每一步彈出了誰、面積是多少。

### 題 B（新變形）：帶存活時間的 LRU cache

這題改自第 27 章核心題 1（146. LRU Cache）。

**題目**：設計一個容量為 `capacity` 的 cache，支援兩個操作，所有呼叫的 `now`（目前時間）都不會遞減：

- `put(key, value, ttl, now)`：寫入或覆寫 `key`，它在時間 `now + ttl` 到期（`ttl ≥ 1`）。如果 `key` 是新的且 cache 已滿，先移除所有已到期的項目；若仍然滿，移除最久沒被使用的項目（LRU）。寫入也算一次使用。
- `get(key, now)`：如果 `key` 存在且尚未到期（`now < 到期時間`），回傳 value 並把它標為最近使用；否則回傳 -1。`get` 不會延長存活時間。

要求兩個操作都接近 O(1) 或 O(log n)。`capacity` 可能為 0，此時任何 `put` 都不保存。

- 範例：容量 2。`put(1, 10, ttl=5, now=0)`、`put(2, 20, ttl=100, now=1)`、`get(1, now=3)` 回傳 10（1 變成最近使用）；`put(3, 30, ttl=100, now=4)` 時已滿且沒有到期的，移除 LRU 的 2；`get(2, now=4)` 回傳 -1；`get(1, now=5)` 回傳 -1，因為剛好到期。
- 邊界：`put(4, 40, ttl=100, now=6)` 時 cache 裡 1 已經被移除，只剩 3，所以不需要再踢掉任何東西，`get(3, 6)` 仍回傳 30。

**參考思路**：原題用 hash map 加雙向 linked list，Python 中可以用 `OrderedDict` 取代（`move_to_end` 與 `popitem(last=False)` 都是 O(1)）。新的需求是「滿的時候先清掉過期的」：如果每次都掃過全部項目找過期者，put 會退化成 O(n)。

觀察是過期項目可以依到期時間排序取出，所以另外維護一個以 `(到期時間, key)` 排序的 min-heap。問題在於同一個 key 可能被覆寫多次，heap 中會留下舊的到期時間；這裡用 lazy deletion（延遲刪除）：彈出 heap 項目時，只有當 cache 中該 key 的到期時間正好等於這個項目時才刪除，否則它是過期的舊紀錄，直接丟掉。`get` 自己檢查到期時間，不需要動 heap。這樣 LRU 順序與到期順序由兩個結構分別負責，各自保持正確。

```text
容量 2 的操作序列：

操作                  OrderedDict（舊 → 新）        heap（到期, key）
put(1,10,5,0)         1:(10,5)                      (5,1)
put(2,20,100,1)       1, 2                          (5,1) (101,2)
get(1,3) → 10         2, 1                          不變
put(3,30,100,4)       已滿；purge(4)：heap 頂 5 > 4，沒有過期
                      仍滿 → 踢 LRU 的 2 → 1, 3     (5,1) (101,2) (104,3)
get(2,4) → -1         1, 3
get(1,5) → -1         5 <= 5 已到期，刪除 → 3
put(4,40,100,6)       未滿，直接加入 → 3, 4         (5,1) 等舊項目留待 purge 時丟棄
```

**參考解法**：

```python
import heapq
import random
from collections import OrderedDict


class TTLCache:
    """容量有限的 LRU cache，每個 key 另有存活時間。呼叫的 now 不會遞減。
    get 只更新最近使用順序，不延長存活時間；now >= 到期時間就視為不存在。"""

    def __init__(self, capacity: int) -> None:
        self.capacity = capacity
        self.data: OrderedDict[int, tuple[int, int]] = OrderedDict()  # key -> (value, expire)
        self.expiry: list[tuple[int, int]] = []                       # (expire, key)，lazy deletion

    def _purge(self, now: int) -> None:
        while self.expiry and self.expiry[0][0] <= now:
            exp, key = heapq.heappop(self.expiry)
            if key in self.data and self.data[key][1] == exp:          # 只刪仍然有效的那一筆
                del self.data[key]

    def get(self, key: int, now: int) -> int:
        item = self.data.get(key)
        if item is None:
            return -1
        value, exp = item
        if exp <= now:
            del self.data[key]
            return -1
        self.data.move_to_end(key)
        return value

    def put(self, key: int, value: int, ttl: int, now: int) -> None:
        if self.capacity <= 0:
            return
        if key in self.data:
            del self.data[key]
        elif len(self.data) >= self.capacity:
            self._purge(now)                                           # 先清掉過期的
            if len(self.data) >= self.capacity:
                self.data.popitem(last=False)                          # 仍然滿：踢掉最久沒用的
        exp = now + ttl
        self.data[key] = (value, exp)
        heapq.heappush(self.expiry, (exp, key))


class TTLCacheBrute:
    def __init__(self, capacity):
        self.capacity = capacity
        self.items = []  # [key, value, expire]，越後面越新

    def get(self, key, now):
        self.items = [it for it in self.items if it[2] > now]
        for i, it in enumerate(self.items):
            if it[0] == key:
                self.items.append(self.items.pop(i))
                return it[1]
        return -1

    def put(self, key, value, ttl, now):
        if self.capacity <= 0:
            return
        self.items = [it for it in self.items if it[2] > now and it[0] != key]
        if len(self.items) >= self.capacity:
            self.items.pop(0)
        self.items.append([key, value, now + ttl])


c = TTLCache(2)
c.put(1, 10, 5, 0)        # 1 在時間 5 到期
c.put(2, 20, 100, 1)
assert c.get(1, 3) == 10  # 1 變成最近使用
c.put(3, 30, 100, 4)      # 滿了，沒有過期的，踢掉 LRU 的 2
assert c.get(2, 4) == -1
assert c.get(1, 5) == -1  # 剛好到期
c.put(4, 40, 100, 6)      # 1 已不在，不用踢 3
assert c.get(3, 6) == 30 and c.get(4, 6) == 40
z = TTLCache(0)
z.put(1, 1, 10, 0)
assert z.get(1, 0) == -1
rng = random.Random(42)
for _ in range(500):
    cap = rng.randint(0, 3)
    a, b = TTLCache(cap), TTLCacheBrute(cap)
    now = 0
    for _ in range(30):
        now += rng.randint(0, 2)
        key = rng.randint(0, 4)
        if rng.random() < 0.5:
            assert a.get(key, now) == b.get(key, now)
        else:
            v, ttl = rng.randint(0, 99), rng.randint(1, 6)
            a.put(key, v, ttl, now)
            b.put(key, v, ttl, now)
print("all tests passed")
```

`get` 是 O(1)。`put` 是攤銷 O(log m)，m 是 heap 大小：每個 heap 項目只會被 push 一次、pop 一次，所以 purge 的總成本不會超過 push 的總次數。對拍用的暴力版本每次操作都先清掉所有過期項目，語意上和「只在滿的時候才清」等價，因為過期項目永遠不會被 `get` 回傳，只影響是否需要踢掉 LRU。

### 面試官可能的追問

- **題 A：如果是二維的 0／1 矩陣，求全是 1 的最大矩形？** 這是第 10 章難題 2（85. Maximal Rectangle）。逐列累積高度：某格是 1 就在上一列高度上加一，是 0 就歸零，每一列都是一個柱狀圖，對每列跑一次本題，O(R·C)。
- **題 A：不用 stack 能做嗎？** 可以先用兩次掃描各算出每根柱子左右第一個更矮的位置（本質上仍是 monotonic stack，或用「跳躍」技巧沿著已算好的邊界往外跳），再逐根計算面積；也可以 divide and conquer：以最矮柱為分界，平均 O(n log n)，但遞增陣列會退化成 O(n²)，除非用 segment tree 找區間最小值。
- **題 A：寬度公式為什麼是 `i − stack[-1] − 1`？** 被彈出的柱子 h 右邊第一個更矮的是 i；彈出後的新 stack 頂端是它左邊第一個比它矮的柱子（或相等，若相等也不影響最大值，因為相等的那根之後會算到更寬的矩形）。兩者之間（不含兩端）都是高度 ≥ h 的柱子，所以寬度是兩索引之差減一。
- **題 B：heap 會不會無限變大？** 會：同一個 key 一直被覆寫時，舊的 heap 項目要等到它們的到期時間過了、而且剛好觸發 purge 才會被丟掉。解法是當 `len(expiry) > 2 * len(data)` 時，用 `data` 中的有效項目重建 heap，O(m) 但攤銷到每次 put 仍是 O(1)，讓空間維持 O(capacity)。
- **題 B：如果 get 要延長存活時間（sliding expiration）？** 每次 get 把新的到期時間寫回 `data`，並 push 一筆新的 heap 項目；lazy deletion 的「到期時間相等才刪」規則照樣能辨認舊項目，所以不需要改其他邏輯。
- **題 B：如果改成依使用頻率淘汰（LFU）？** 這是第 27 章難題 1（460. LFU Cache）：每個頻率一個 `OrderedDict`，再記錄目前的最小頻率，所有操作 O(1)。到期處理可以沿用本題的 heap 與 lazy deletion。
- **題 B：不用 OrderedDict 要怎麼寫？** 自己實作雙向 linked list，用 head 與 tail 兩個哨兵節點（sentinel）避免處理空串列的特例；hash map 存 key 到節點的對應。面試官要求手寫時，先寫 `_remove(node)` 與 `_add_to_end(node)` 兩個輔助函式，主流程只呼叫它們。

### 評分重點

| 維度 | 這一場的 L5 表現 |

| Problem solving | 題 A 從「每根柱子作為最矮柱」推出需要左右第一個更矮的位置；題 B 指出覆寫造成的舊 heap 項目，並提出 lazy deletion |
| Coding | 題 A 用尾端哨兵處理剩餘的 stack；題 B 的類別結構清楚，把 purge 抽成輔助函式，覆寫已存在 key 時不觸發淘汰 |

| Communication | 題 B 寫程式前先列出介面與兩個資料結構各自的責任；題 A 的寬度公式能用一句話解釋 |

讀這張表時，請特別注意那些訊號重疊的列，例如「連續子陣列」同時出現在第 6 章與第 7 章：有負數時窗口的單調性不成立，要改用 prefix sum；「最少步數」同時出現在第 15 章與第 18 章：等權用 BFS，加權用 Dijkstra。第 3 章 3.6 節詳細討論了這些容易混淆的組合，模擬面試中卡住時，回頭問自己「是哪個條件讓這兩個 pattern 分開」，往往就能找到方向。

## 本章重點整理

- 模擬面試要盡量接近真實：45 分鐘計時、出聲、不執行程式、做完才看答案，並在結束後立刻填自我檢討表。
- 每場兩題、來自不同 pattern，是為了練習切換思考模式；第一題要在約 22 分鐘內結束，否則第二題很難完成。
- 題 A 檢查核心題熟練度，重點不在寫出程式，而在說得出關鍵理由，例如 128 的 amortized 分析、236 的回傳值語意、84 的寬度公式。
- 題 B 的新變形都能從原題推出：把布林判斷換成可增量維護的計數、把一個 heap 拆成兩個順序、把晚出發的來源分層注入、把布林 DP 換成最小值 DP、把折價券放進狀態、用 lazy deletion 處理到期。
- 「把額外資源或條件放進狀態」是最常見的變形手法之一，出現在分層 Dijkstra、BFS 的 visited 鍵與 DP 的維度中。
- 很多直覺做法可以用一個小反例推翻，例如「先找最短路再打折」「只用一個 heap 分配會議室」；在設計階段主動找反例，是 problem solving 的強烈訊號。
- 驗證時要用暴力解對拍，值域刻意很小；本章每段參考解都示範了這種寫法。
- 評分以四個維度各 1–4 分自評，L5 的合理期待是全部至少 3 分；任何一項 2 分以下就是考前要優先補強的短板。
- 把六場的檢討表中所有「否」集中起來，重複出現的項目才是你真正的弱點，比單場分數更有參考價值。
- Pattern 全回顧表在每場前讀一次，面試前一天遮住右兩欄自我測驗；特別注意訊號重疊的 pattern 用哪個條件區分。

## 延伸問答

> [!question]- Q1. 沒有練習夥伴，一個人做模擬面試有效嗎？
> 有效，但要刻意補上「被打斷」與「被觀察」這兩個缺口。被觀察的部分用錄音或錄影取代：全程出聲，結束後回放，檢查沉默的時間、關鍵決策有沒有說出理由、複雜度說明是否完整。被打斷的部分可以事先把「面試官可能的追問」抄在卡片上並打亂，寫完一題後隨機抽兩張，限時三分鐘口頭回答，再對照答案要點。一個人練習最容易放水的地方是時間，所以計時器一定要開，時間到就停筆，沒寫完的部分在檢討表中誠實記錄。

> [!question]- Q2. 如果題 A 一眼就認出來，還要花時間講暴力解嗎？
> 要講，但壓縮到一兩句話，例如「暴力解是對每個數往上數，O(n²)；瓶頸是同一段連續序列被不同起點重複數，所以只從起點開始」。這樣做有兩個目的：讓面試官看到你理解解法為什麼成立，而不是記得答案；同時替後面的追問鋪路，因為很多追問就是在改變那個瓶頸成立的條件。真實面試中，面試官也可能故意出你看過的題目，看的正是你能不能說清楚理由。省下來的時間應該花在驗證與追問上，而不是省略推導。

> [!question]- Q3. 做完一場發現四個維度都只有 2 分，該怎麼辦？
> 先不要急著做下一場，因為同樣的問題會重複出現。回頭看檢討表，找出最根本的原因：如果是 problem solving 低，通常代表核心題還不夠熟，應該回到對應章節，把那兩題的核心題與同章的其他核心題重新限時寫一次；如果是 coding 低，多半是寫程式前沒有先說出結構，下次強迫自己在動手前用一句話講出骨架；如果是 verification 低，就把「寫完先追蹤一個範例與一個邊界」寫在紙上貼在螢幕旁。修正之後隔一天再做下一場，並把同一場的兩題換成同章的其他核心題重做一次，確認問題真的改善了。

> [!question]- Q4. 新變形題和原題差很多，怎麼判斷該從哪道原題出發？
> 先不要找原題，而是先把題目要求的量用一句話寫成定義，例如「每格的腐爛時間是所有來源的 t_i 加距離的最小值」或「最少替換數是窗口長度減去能對上的字元數」。定義寫出來後，問自己這個量的結構像哪個 pattern：最小值加距離是最短路，固定長度窗口上的計數是 sliding window，前綴上的最小值是 DP。接著才回想書中哪道題有相同結構，再比較兩者的差異在哪裡、哪個假設被打破了。本章六道新變形都是這個流程：定義、結構、原題、差異、修正。

> [!question]- Q5. 兩題的形式中，第一題卡住超過 20 分鐘，要不要放棄去做第二題？
> 通常不建議由你自己宣布放棄，而是先和面試官溝通現況：說出你目前有的做法（即使是暴力解）、卡在哪裡、還需要多少時間。很多面試官會在這時給提示，或主動說「我們先換下一題」。如果你完全沒有可行解，最好先用三到五分鐘把暴力解寫出來，這樣至少在 coding 與 verification 上有可評估的內容，再請求進入第二題。真正要避免的是悶著頭繼續想到時間結束，讓兩題都沒有成果；部分完成的兩題，通常比一題做完、一題沒碰的評價更穩。

> [!question]- Q6. 參考解法都附了隨機對拍，真實面試中也要寫對拍嗎？
> 多數面試環境不能執行程式，所以不需要寫完整的對拍程式，但可以用一句話說出你會怎麼做：「如果能執行，我會寫一個逐間掃描的暴力版本，用值域很小的隨機輸入對拍。」這顯示你有系統化的驗證習慣。在面試中真正要做的是手動追蹤：挑一個能觸發關鍵邏輯的小例子，例如會議室題中「多間同時空閒」的案例。對拍的主要價值在練習階段：它能找出你自以為正確的漏洞，並告訴你最小的失敗輸入，讓你知道下一次手動追蹤該挑哪種例子。

> [!question]- Q7. 面試官的追問超出我準備的範圍，例如第六場被問到多執行緒怎麼辦？
> 先確認問題的範圍，例如「你是指多個執行緒同時呼叫 get 與 put，需要保證每個操作的原子性嗎？」接著從你已經有的結構出發推理，而不是背答案：OrderedDict 與 heap 都不是執行緒安全的，最直接的做法是用一把鎖保護整個操作，正確但會限制並行度；進一步可以把 key 依雜湊分成多個分片，每個分片各自一把鎖與一份 LRU，代價是 LRU 只在分片內精確。說出取捨比給出完美答案更重要。如果真的不熟，誠實地說出你知道的部分與你會怎麼查證，也比含糊帶過好。

> [!question]- Q8. 六場都做完、成績也不錯，最後幾天還要做什麼？
> 把重點從「學新東西」轉到「穩定發揮」。第一，把六場檢討表裡的「否」再看一次，針對重複出現的項目各做一兩次短練習，例如專門練習寫完後的手動追蹤。第二，每天限時重寫兩到三道核心題，挑你最沒把握的 pattern，用 31.8 節的全回顧表確認每個 pattern 的模板要點都能不看書說出來。第三，把本章的六道新變形換個條件重做，例如把折價券改成兩張、把會議室改成固定數量，練習把熟悉的技巧搬到新題目上。最後一天不要再做完整的模擬面試，讀第 30 章的面試當天檢查清單，保持睡眠與狀態。
