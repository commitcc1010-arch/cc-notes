## Audit-wide findings

- All eight chapters reuse the same five-question skeleton. Q1 and Q5 repeat the broad architecture; Q2 and Q4 repeat the primary-service settings bundle; Q3 tests a service definition already disclosed by the chapter.
- The repeated distractors—use defaults, increase capacity and budget only, deploy every option, grant organization-wide administrator access, or create an empty second Region—are implausible and do not discriminate architectural knowledge.
- Several “alternatives” are valid dimensions of the nominal answer rather than mutually exclusive choices: active-active is a data-conflict decision, pool/silo/bridge is a tenancy model, managed versus self-managed transcoding is an implementation boundary, and backup/restore can be correct for a workload with a looser recovery objective.
- A single primary service is repeatedly credited with end-to-end behavior that belongs to application state, identity, networking, data semantics, operations, or recovery. The replacement intents separate those contracts.
- Every chapter below is audited independently and has exactly ten numbered intents. Every intent contains a hard constraint, one correct principle, exactly three plausible distractor concepts, an SAA-C03 or SAP-C02 task mapping, and official AWS documentation source keys.
- At least one intent per chapter requires multi-response reasoning: multiple controls are independently necessary, and selecting only one leaves a stated hard constraint unmet.

## Chapter 97 — Global Ecommerce Platform

### Defects in the current questions

- **Duplicate/low-density:** Q1 and Q5 repeat the same edge/stateless/queue/single-writer architecture; Q2 and Q4 repeat the same CloudFront settings; Q3 repeats the CloudFront request path.
- **Factual error:** Q1's explanation attributes inventory consistency, payment idempotency, burst absorption, and cross-Region recovery to CloudFront. CloudFront does not own transaction semantics, writer promotion, queue capacity, or recovery orchestration.
- **Factual incompleteness:** Q4 selects only CloudFront settings even though the stated constraints also require an authoritative transaction store, idempotency state, asynchronous backpressure, and a failover plan.
- **Ambiguity:** Active-active is treated as categorically wrong even though it is a valid topology when the data model has defined conflict semantics. The explanation's Global Accelerator “flip signal” is unrelated to inventory/payment conflict resolution.
- **Weak distractors:** “Deploy all options,” “managed services automatically cross Regions,” and “use the service defaults” are implausible and allow guessing without understanding cache correctness or transaction safety.
- **Missing coverage:** Personalized-response caching, OAC/origin bypass, WAF versus authorization, durable payment idempotency, queue age, graceful recommendation degradation, writer fencing, failback, and cost per successful checkout are not tested.
