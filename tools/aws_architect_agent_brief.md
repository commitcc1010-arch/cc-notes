# 撰寫任務說明（給章節撰寫 agent）

你正在參與重寫《AWS Solutions Architect 雙證全攻略》。舊版是用範本程式產生的，可讀性很差、套句大量重複、知識點講不清楚。新版要全部手寫，成為一本初階 engineer 也能讀懂、可以拿來準備 AWS SAA-C03 與 SAP-C02 的參考書：內容 self-contained、深度與廣度都夠，而且每章都有完整敘事，讓讀者循序漸進。

## 開始前必讀（依序）

1. `tools/aws_architect_style_guide.md`：寫作規範。**全部遵守**，特別是第 3 節章節結構、第 4 節禁止事項、第 5 節練習題格式、第 7 節準確性重點。
2. `tools/aws_architect_outline.md`：全書大綱。找到你負責章節的「必須涵蓋」清單，全部都要講到；同時了解其他章講什麼，交叉引用時寫「第 N 章」，並避免重複其他章的主題（例如你寫 RDS 章，就不要重講 KMS 原理，簡述後指向第 15 章）。
3. `AWS Solutions Architect/Part 1 - Networking/05 - VPC 從零到可上線.md`：**全書範本章**。仔細讀完，學它的敘事方式、深度、圖解、表格、callout、考試小節與練習題品質。你寫的章要達到同樣或更好的水準。

## 參考舊稿（只當素材，不要照抄）

- `/tmp/aws_old/chapters/chNNN.md`：舊版章節（NNN 是三位數舊章號，對應見大綱的「舊章」欄）。正文大多是範本套句，**不要沿用它的結構和句子**。其中「跨來源稽核後補上的進階缺口」這類段落、設定範例、route table 範例通常是手寫的，可以吸收其中正確的知識點。
- `/tmp/aws_old/questions/chNNN.md`：舊版章內題目（品質不錯）。好題可以改寫後收錄（要符合新格式、修正錯誤），但至少一半題目要是新題。
- 舊稿裡的 AWS 官方連結都已查證過，可以使用；不要自己編造 URL。

## 你要產出的檔案

只能建立或修改分配給你的檔案（路徑見大綱），不要動其他任何檔案。

## 寫作要求重點（再次強調）

- 讀者是零雲端背景的初階 engineer。每個新名詞第一次出現都要用白話解釋；每個機制都要講「為什麼需要、怎麼運作、AWS 怎麼做、常見誤解」。
- 每章用 Wanderly 案例或具體場景開場，各節之間要有承接，讓整章是一個連貫的故事，而不是條列清單。
- 深度：覆蓋大綱「必須涵蓋」的全部項目，還要補上你知道的、SAA／SAP 考試會考的重要細節。核心章正文約 15,000–30,000 可見字元（不含題目）。
- 至少一張 ASCII 架構／流程圖，圖後逐步解說。
- 要有「比較與選型」表格與「考試這樣考」小節（關鍵字對照表至少 8 列 + 常見陷阱）。
- 題目：題數依大綱；格式嚴格依照規範第 5 節；選項要都看似合理；答案字母分散；每個選項都要有教學式解析；考點標官方 task ID。
- 準確性第一：只寫你有把握的事實。不確定的數字寧可不寫或寫「預設 quota，可申請提高」。已停止或對新客戶關閉的服務要說明現況。

## 自我檢查（必做）
