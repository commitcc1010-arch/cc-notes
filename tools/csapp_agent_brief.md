# 撰寫任務說明（給章節撰寫 agent）

你正在參與重寫《CS:APP 系統思維學習手冊》。舊版是在原始筆記上不斷疊加「enrichment」區塊產生的：每章充滿範本化的卡片標題、中英文黏在一起、內容破碎、缺少循序的敘事。新版要全部手寫：讓只會高階語言的工程師與學生讀得懂，循序漸進地理解 CS:APP 3e 的全部核心觀念，深度與廣度兼備，並有足夠的實務例子讓讀者知道「這些底層知識在工作上什麼時候會用到、怎麼用」，搭配大量圖表與流程圖輔助理解。

## 開始前必讀（依序）

1. `tools/csapp_style_guide.md`：寫作規範，全部遵守，尤其第 2 節（中英文之間加空格、視覺化要求）、第 3 節（章節結構）、第 4 節（程式碼規則）、第 7 節（準確性）、第 8 節（禁止事項）。
2. `tools/csapp_outline.md`：全書大綱。找到你負責章節的「必須涵蓋」清單，全部講到，並補上你知道的重要知識點與現況。了解其他章講什麼，交叉引用寫「第 N 章」，避免重複其他章的主題。
3. `CSAPP 系統思維學習手冊/Part 7 - 虛擬記憶體/23 - 位址轉譯.md`：**全書範本章**。仔細讀完，學它的敘事、深度、手算算例、圖表密度、程式與輸出解說、「在工作上怎麼用」與問答品質。你寫的章要達到同樣或更好的水準。

## 重點要求

- 每個新名詞第一次出現就白話解釋並舉例；每個機制講清楚「為什麼需要、怎麼運作、在真實系統長什麼樣、常見誤解」。數值類主題一定要有完整手算算例。
- 用 `thumbd` 的真實問題開場，並在整章中持續使用它的情境。
- 正文約 14,000–25,000 可見字元（不含問答與程式碼）；至少 3 張 ASCII 圖與 3 張表格。
- 「動手做」：至少一段可直接執行的 C（或 Python）程式；**實際編譯執行**後把輸出貼在緊接的 ```text 區塊，註明執行環境（例如 macOS arm64 或 Linux x86-64）；再逐步解說。本機是 macOS arm64，只能在 Linux 執行的程式第一行寫 `// linux-only`。
- 組合語言一律用 `clang -target x86_64-linux-gnu -O1 -S -fno-asynchronous-unwind-tables -o - file.c` 實際產生（本機可以執行這個指令），不要憑記憶手寫。
- 「在工作上怎麼用」要具體：真實工作情境、工具指令、判斷流程或檢查清單。
- 準確性第一：不確定的數字或行為就不寫，或標明依平台而定。
