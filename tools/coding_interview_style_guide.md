# 《Coding Interview Pattern Playbook》寫作規範

所有章節都必須遵守本規範。`tools/check_coding_interview_book.py` 會自動檢查可機器驗證的部分。

## 1. 讀者與目標

- **讀者**：會寫 Python、學過基本資料結構（陣列、hash table、linked list、tree、graph 的概念），準備 Google、Meta、Amazon 等公司 coding interview 的工程師與學生。
- **標準**：以 Google L5（senior）同等級的 coding interview 為準：能在時間內寫出最佳或接近最佳的解、程式乾淨、主動測試與處理邊界、清楚說明複雜度與取捨，並能應付面試官連續的 follow-up。每題的思路、follow-up 與心得都要以這個標準撰寫。
- **目標**：在 2–3 週內讀完，理解 26 個 pattern 的原理、辨識方式與所有主要變形；看到新題目時能判斷該用哪個 pattern，並寫出正確、可解釋的解法。
- **自給自足**：讀者不需要打開 LeetCode 就能理解每一題。題目要完整重述（輸入、輸出、限制、範例），解法要從思路講到程式。
- **不照抄**：題目一律用自己的話重述，範例可以自己設計；不要逐字複製 LeetCode 題目原文。
- 引用其他章節寫「第 N 章」；引用同一本書的其他題寫「第 N 章核心題 k」或「第 N 章難題 k」。

## 2. 語言與格式

- 繁體中文（台灣用語），演算法術語保留英文（two pointers、sliding window、monotonic stack、memoization），第一次出現附中文解釋。
- **中英文之間一定加半形空格**；中文句子用全形標點。
- 段落 3–6 句。解題思路要有因果：「因為……所以……」，不能只列結論。
- 每題至少一個 ```` ```text ```` 視覺化：陣列與指標移動、窗口變化、遞迴樹、DP 表格填寫過程、圖的 BFS 層次等，並用文字逐步解說。
- 程式只用 Python 3.11+ 與標準函式庫。

規則：

- 開頭的編號小節（`## 8.1`…）至少 4 節，必須包含「辨識訊號」「模板」「常見錯誤」三節（標題以這些字開頭或包含這些字）。
- 題目標題格式嚴格為 `## 核心題 k｜<題號>. <英文題名>｜<Easy／Medium／Hard>` 或 `## 難題 k｜…`。題號與順序必須和大綱一致；難度寫 LeetCode 官方難度（難題區的題目不一定標 Hard）。
- 每題的 H3 小節依序固定：核心題是「題目、思路、解法、複雜度與邊界、Follow-up」；難題是「題目、提示、詳解、解法、複雜度與邊界、Follow-up、心得」。
- 最後兩個 H2 固定為「Pattern 歸納」「本章重點整理」。

### 各小節要寫什麼

- **題目**：完整重述（輸入、輸出、限制條件），至少兩個範例（含一個邊界情況）。
- **思路**（核心題）：先講暴力解與其複雜度，再講瓶頸在哪、如何用本 pattern 改進；關鍵的 invariant 要明說。附一個 ```text 視覺化逐步走過範例。
- **提示**（難題）：三段由淺到深的提示，每段用一個 `> [!tip]- 提示 1` 摺疊 callout；第一段只點方向，第三段接近完整思路。
- **詳解**（難題）：完整推導，說明為什麼直覺做法行不通、關鍵突破點、正確性理由，附 ```text 視覺化。
- **解法**：一段可直接執行的 Python。函式之後用 `assert` 測試至少 3 個案例（含範例與邊界），最後一行 `print("all tests passed")`。checker 會執行它。若有多種解法（例如 O(n²) 與 O(n log n)），可以放多段程式，每段都要能執行。
- **複雜度與邊界**：時間與空間複雜度，並說明為什麼；列出要注意的邊界情況（空輸入、重複、溢位、負數、全部相同…）。
- **Follow-up**：至少 3 個，**必須針對本題**，是面試官真的會追問的變形，例如「如果輸入是串流」「如果要回傳所有解」「如果 k 很大」「如果改成二維」「能否 O(1) 空間」。每個用 `> [!question]- F1. 問題` 摺疊 callout，答案要具體：說明做法、複雜度，必要時附短程式。答案至少 80 可見字元。
- **心得**（難題）：這題的關鍵突破點一句話、和本章其他題的關係、面試時怎麼講。

### Pattern 歸納

- 一張表列出本 pattern 的所有主要變形：變形｜辨識方式｜關鍵技巧｜本章題目／其他經典題。
- 「下限與上限」：最簡單的形式長什麼樣、最難的題目難在哪裡（多個 pattern 組合、需要額外觀察、需要進階資料結構）。
- 與其他 pattern 的關係與容易混淆之處。

## 4. Guide 章結構（第 1–3、30–31 章）

```markdown
---
chapter: 2
title: 面試流程與溝通
part: 0
---

# 第 2 章　面試流程與溝通：從題目到通過

> [!abstract] 本章地圖
> **核心問題**：……
>
> **你會學到**：
> - ……

## 2.1 ……
## 2.k ……
## 本章重點整理
## 延伸問答
```

- 編號小節至少 4 節；最後兩個 H2 是「本章重點整理」「延伸問答」。延伸問答 8 題，格式 `> [!question]- Q1. 問題`，答案至少 120 可見字元。

## 5. 準確性與禁止事項

- 每段程式都要真的能通過自己的測試；複雜度要正確；不要宣稱錯的最佳解。
- 不確定的公司面試資訊不要寫成事實；不要捏造題目出現頻率或統計數字，只能寫「常見」「公開面經中經常出現」這類定性描述。
- 禁止舊版的範本化套句：「視覺化題解：從暴力到最佳模型」「五步推導」「原題直接變形」「正確性證明骨架」「這題真正考什麼」「production API」「一句話記憶」。
- Follow-up 不得是可以套用到任何題目的通用問題（例如「如果改成線上更新、超大資料或 production API」）。
- 不要放 URL（LeetCode 題號已足夠查找）。
