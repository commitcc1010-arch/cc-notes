# 撰寫任務說明（給章節撰寫 agent）

你正在參與重寫《從 Commit 到可靠服務：Software Engineering × SRE × AI》。舊版是由 Python 範本資料產生的：每章只有約 4,000 字的實質內容，大量套句重複，概念講得太淺、知識點不完整。新版要全部手寫：讓有 0–3 年經驗的工程師讀得懂、學得完整，內容自給自足，有深度與廣度，每章都是一個循序漸進的完整故事。

## 開始前必讀（依序）

1. `tools/swe_sre_ai_style_guide.md`：寫作規範，全部遵守，尤其第 3 節（章節結構）、第 4 節（禁止事項）、第 5 節（延伸問答格式）、第 7 節（準確性）。
2. `tools/swe_sre_ai_outline.md`：全書大綱。找到你負責章節的「必須涵蓋」清單，全部都要講到，並補上你知道的重要知識點與業界現況。了解其他章講什麼，交叉引用寫「第 N 章」，避免重複其他章的主題（簡述後指向該章即可）。
3. `Software Engineering SRE AI/Part 5 - SRE 與可靠性模型/32 - SLI SLO SLA 與 Error Budget.md`：**全書範本章**。仔細讀完，學它的敘事方式、深度、圖解、表格、程式範例與解說、AI 小節與問答品質。你寫的章要達到同樣或更好的水準。

## 重點要求

- 讀者沒有大型組織經驗。每個新名詞第一次出現就白話解釋並舉例；每個機制講清楚「為什麼需要、怎麼運作、實務怎麼做、常見誤解」。
- 用 Harbor 港灣市集開場，並在整章中持續使用 Harbor 的情境，讓概念落地。注意大綱第 6 節的時間線（公司規模隨 Part 成長）。
- 深度：涵蓋大綱「必須涵蓋」全部項目，正文約 14,000–25,000 可見字元（不含問答與程式碼）。
- 「動手寫」：至少一段只用標準函式庫、可直接執行的 Python 3 程式，模擬本章機制；**實際執行**後把輸出貼在緊接的 ```` ```text ```` 區塊；再逐步解說程式與真實系統的對應。
- 「AI 時代：什麼變了？」要具體、可執行，附「適合交給 AI 的工作｜必須保留的人類判斷與 guardrails」表格。
- 準確性第一：引用原書概念要正確；研究數據、產品功能不確定就不寫。
