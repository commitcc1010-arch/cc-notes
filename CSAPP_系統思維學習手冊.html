每個概念固定問四件事

1. 它解決什麼問題？

先找需求。例如 cache 是為了縮小 CPU 與 DRAM 的速度差，不要從 tag bits 開始背。

2. 對外契約是什麼？

呼叫者可依賴什麼？哪些細節只是實作？例如 TCP 保證 byte order，不保證 message boundary。

3. 狀態放在哪裡？

Register、process、kernel、cache、disk 還是 peer？找對 state owner，才能推導 lifetime 與 race。

4. 如何觀察與推翻？

用 assembly、counter、trace、core dump 或最小實驗驗證，不把示意圖當成真實執行證據。

0.3 Declaration、definition 與 header

Declaration 告訴 compiler 名稱的型別；definition 真正提供 function body 或配置 object storage。Header 應放介面宣告、型別、常數與 include guard；通常不要 include .c。一個 external object 可在 header 寫 extern int counter;，再於某個 .c 寫一次 int counter;。

0.4 Undefined behavior 為何比「隨機結果」更嚴重

Undefined behavior（UB）代表語言規格不再限制結果。Compiler 可假設合法程式不會發生 UB，再據此刪除分支或重排程式。常見來源：signed overflow、越界、use-after-free、無效 shift、違反 alignment、data race、錯誤 format specifier。

初學者安全編譯選項 開發期使用 -Wall -Wextra -Wconversion -Wshadow -g，再分別測 -O0 與 -O2；搭配 -fsanitize=address,undefined。Warning 不是全部錯誤，但每一個都應理解後處理。

先備題 1：sizeof(pointer) 為何不能得知 allocation 大小？

Pointer value 只保存地址，其型別通常不攜帶被指向 allocation 的長度。sizeof p 得到 pointer 本身大小。長度必須由 API 額外傳入、包在 struct 中，或由 allocator 的私有 metadata 管理。

先備題 2：free(p) 後把 p = NULL 是否完全解決 use-after-free？

只清除這一個 pointer variable。其他 alias 仍可能保存舊地址，而且若程式先透過 alias 使用再清除也沒有幫助。真正策略是清楚 ownership、限制 alias、讓釋放點唯一，必要時用 sanitizer 驗證。

先備題 3：為何 char *p + 1 和 int *q + 1 前進距離不同？

Pointer arithmetic 以 pointed-to type 的元素為單位。前者加一個 char，通常 1 byte；後者加一個 int，通常 sizeof(int) bytes。這讓 q[i] 能定義成 *(q+i)。

先備題 4：exit status、errno、signal 三者差在哪？

Exit status 是 process 正常結束時回給 parent 的小整數狀態；errno 是許多 library/system-call wrapper 在失敗後提供的 thread-local 錯誤代碼，只有 API 表示失敗時才讀；signal 是可非同步送達 process/thread 的通知機制。

系統全景：Hello World 背後發生什麼事

1.1 編譯系統四步驟

階段輸入 → 輸出主要工作常用觀察工具

把四步驟親眼看一次

// hello.c
#include <stdio.h>
int main(void) {
    puts("hello");
    return 0;
}

$ cc -E hello.c -o hello.i
$ cc -S hello.i -o hello.s
$ cc -c hello.s -o hello.o
$ cc hello.o -o hello
$ file hello hello.o
$ nm hello.o
$ ./hello

你會看到 hello.o 還不是可直接執行的完整程式：它引用外部的 puts。最後 link 產生 executable，執行時 dynamic loader 與 C library 再參與。這也是為何「我的原始碼只有五行」不代表 process 只有五行工作。

1.2 執行時的分工

應用程式：演算法、資料結構、商業邏輯
    ↓ library call / system call
作業系統：行程、虛擬記憶體、檔案、裝置、網路、保護
    ↓ ISA（軟硬體契約）
處理器：取指、解碼、執行、推測、退休
    ↓ address / data
記憶體階層：register → L1/L2/L3 → DRAM → SSD / network

ISA 是編譯器與 CPU 之間的契約；ABI 再加入 calling convention、資料布局、object format 等二進位相容規則；API 則是原始碼層級的介面。

從按下 Enter 到看到 hello

  1. Shell 解析命令，通常建立 child process。
  2. Child 透過 execve 請核心載入 executable。
  3. Kernel 檢查格式與權限，建立新的 virtual address space mappings。
  4. Dynamic loader 載入 shared libraries 並完成需要的 relocation。
  5. Runtime 啟動程式，最終呼叫 main。
  6. puts 整理輸出，最後以 system call 把 bytes 交給 kernel。
  7. Terminal driver 與顯示系統讓字元出現在畫面。
卡關：CPU、OS、library 到底誰在做事？ 看 privilege 與 state owner。一般字串處理可在 user mode library 完成；檔案、網路、process、page table 等受保護資源由 kernel 管理；算術與指令執行由 CPU 完成。一次高階 API 呼叫可能跨越多層。

1.3 Amdahl 定律：最佳化前先找占比

若某部分占總時間比例為 α，該部分加速 k 倍，整體加速比是：

Speedup = 1 / ((1 - α) + α / k)

一段只占 5% 的程式，即使變成零成本，整體最多也只快約 1.053 倍。這是「先 profile 再最佳化」的數學理由。

工作應用：跨層事故定位 API p99 變慢時，依序切分 CPU time、blocked time、page faults、storage/network latency。先找時間消失在哪一層，再針對該層取證。
理解題：library call 和 system call 有何不同？

Library call 是呼叫使用者空間的函式，例如 strlen；不一定進入核心。System call 是受控地切換到核心，請求作業系統執行特權操作，例如 read。printf 是 library call，但最後通常透過 write system call 輸出；中間可能先經過 stdio buffer。

理解題：程式已經 link 完，為何啟動時仍可能出現 shared library error？

Link time 可只記錄 executable 需要哪些 shared objects 與 symbols；真正的 library 搜尋與部分 binding 發生在 load/runtime。部署環境可能缺檔案、搜尋路徑不同、ABI 或 symbol version 不相容。

工具題：如何確認 hello 實際呼叫了哪些 system calls？

在 Linux 使用 strace -f ./hello。先找 execve、library mappings，再找輸出的 write。實際 trace 會比想像長，因為 loader、locale 與 runtime 初始化也需要系統資源。

資訊表示：位元沒有型別，解讀方式才有

核心直覺 記憶體只保存 bit pattern。同一串位元可以被解讀為整數、浮點數、指標或指令。Bug 常發生在兩種解讀規則的交界。
讀前確認：先能把一個 byte 看成 8 bits，並知道十六進位一位對應 4 bits。所有公式都先用 4-bit 或 8-bit 小模型手算，再推廣到 32/64-bit。

2.1 二進位、十六進位與 byte order

十六進位每一位剛好對應四個 bit，適合閱讀地址與 bit mask。若整數 0x12345678 從低地址開始存成 78 56 34 12，就是 little-endian；網路協定傳統上使用 big-endian，也稱 network byte order。

2.2 Unsigned 與 two's complement

2.3 C integer promotions 與 conversion 排查法

  1. 先標出每個 operand 的實際型別與寬度。
  2. 小於 int 的整數型別通常先做 integer promotion。
  3. Binary operator 再做 usual arithmetic conversions，讓兩邊有共同型別。
  4. 運算在共同型別中發生，最後才轉到 assignment target。
int x = -1;
unsigned int y = 1;
if (x < y) {
    /* 常見平台上不會進來：x 先轉成很大的 unsigned */
}
卡關：cast 能不能修 overflow？ 要在運算「之前」提升 operand。(long)(a * b) 仍先以原型別相乘，overflow 後才 cast；應寫 (long)a * b。Cast 只改解讀/轉換規則，不會回到過去修復已發生的錯誤。
最常見的 C 陷阱：signed / unsigned 混算 比較時若 signed 被轉成 unsigned，負數會變成很大的正數。陣列長度、差值和倒序 loop 特別危險。長度用 size_t，差值用 ptrdiff_t，並避免寫 for (size_t i = n - 1; i >= 0; --i)。 
#include <stdint.h>
#include <stdbool.h>

bool add_overflow_i32(int32_t a, int32_t b, int32_t *out) {
    int64_t wide = (int64_t)a + (int64_t)b;
    if (wide > INT32_MAX || wide < INT32_MIN) return true;
    *out = (int32_t)wide;
    return false;
}

2.4 Bit hacks 要先寫出語意

  • x & (x - 1) 清掉最低的 1；可用於計算 set bits 或檢查 power of two。
  • x & -x 取出最低的 1；成立的前提是 two's complement，並要小心 signed 最小值。
  • 設定、清除、切換第 k 位：x | mask、x & ~mask、x ^ mask。
  • 右移 signed 負數是否做 arithmetic shift 與語言規格、實作有關；協定解析優先用 unsigned。

2.5 IEEE 754 浮點心智模型

一般 normalized binary floating point 可寫成 (-1)^s × 1.f × 2^E。指數全 0 表示 zero 或 subnormal；全 1 表示 infinity 或 NaN。浮點數密度隨數值大小改變，因此它提供相對精度，不是固定小數位。

以 binary32 為例，1 個 sign bit、8 個 exponent bits、23 個 fraction bits。Normalized number 的真實指數是 E = encoded_exponent - 127，有效數有隱含的 leading 1；subnormal 沒有隱含 1，讓數值能逐步靠近 0，形成 gradual underflow。預設 round-to-nearest, ties-to-even 可降低長期統計偏差。

深化題：為何 abs(INT_MIN) 可能出問題？

w-bit two's complement 的最小值是 -2^(w-1)，最大值只有 2^(w-1)-1，正值範圍少一個。因此最小值沒有可表示的正相反數。安全做法是先提升到更寬的型別，或在取絕對值前特別處理最小值。

深化題：如何判斷 unsigned 加法 overflow？

令 sum = a + b。Unsigned 算術會對 2^w 取模，因此若發生 wraparound，sum < a（也會小於 b）。C23 或編譯器 builtin 也提供 checked arithmetic；正式程式優先使用標準或 builtin，避免自行遺漏型別細節。

深化題：8-bit 的 0xFF sign-extend 到 16-bit 是什麼？

若先把它解讀為 signed 8-bit 的 -1，sign extension 複製最高位，得到 0xFFFF，仍表示 -1。若它是 unsigned 8-bit 的 255，zero extension 得到 0x00FF。

深化題：為何浮點加法不具 associativity？

每一步結果都可能 round。(a+b)+c 與 a+(b+c) 的中間值大小與被捨棄 bits 不同，因此最後 representation 可不同。平行 reduction 改變加總樹，也可能改變低位結果。

Stack buffer overflow 可能覆寫 return address。現代防禦包括不可執行記憶體（NX）、位址隨機化（ASLR）、stack canary、PIE 與 control-flow protection。ROP 不注入新程式碼，而是串接既有 code snippets，因此單靠 NX 不足以阻止控制流劫持。

工作應用：讀 core dump 先看 signal 與 fault address，再用 bt 找 call chain、frame 切換、info registers 看參數與指令位置、x 檢查記憶體。若最佳化使變數消失，對照 disassemble /m 與 ABI 推回值的來源。

解題：看到 test rax, rax; je ... 應如何理解？

解題：cmp a,b 後該用 signed 還是 unsigned jump？

4.0 Combinational logic 與 sequential state

Combinational logic 的輸出只由當前輸入決定，例如 ALU、adder、mux；sequential element 保存跨 cycle 的 state，例如 PC、register file、pipeline registers。Clock period 必須容納一個 stage 的最慢 combinational path 加上 register overhead，這條最慢路徑稱 critical path。

4.1 Sequential datapath

  1. Fetch：依 PC 讀指令並算 next PC。
  2. Decode：解析 opcode、讀 register operands。
  3. Execute：ALU 算術、地址計算或條件判斷。
  4. Memory：需要時讀寫 data memory。
  5. Write-back：把結果寫回 register file。
  6. PC update：選擇 sequential、branch、call 或 return target。

4.4 Branch prediction 與 speculation

處理器在 branch 結果確定前先猜路徑並執行。猜對可維持 pipeline；猜錯必須丟棄 speculative work。資料分布難預測的 branch 會帶來成本；但是否改成 branchless code 仍需量測，因為 branchless 可能增加指令與資料依賴。

安全邊界 Architectural state 被回滾，不代表 microarchitectural footprint 完全消失。Speculative execution 可能透過 cache timing 等 side channel 洩漏資訊，這也是 Spectre 類問題的根源。
工作應用：讀 CPU 指標 IPC 低不等於 CPU 不忙。搭配 cycles、instructions、branch-misses、cache-misses、frontend/backend stalls 判讀。先用 profile 找 hot path，再看造成 stall 的依賴、記憶體或分支。
卡關：stall 和 bubble 有何不同？ Stall 是某個 pipeline register 保持原值，讓指令暫停；bubble 是把該 stage 的控制訊號改成無副作用的 NOP，讓後方舊指令繼續排空。實作 hazard control 時必須明確指出哪個 register stall、哪個 register bubble。
推理題：pipeline 深度增加一定更快嗎？

不一定。較短 stage 可提高 clock frequency，但 pipeline register 有成本，branch misprediction 要丟棄更多 stage，資料依賴也可能增加等待。效能取決於時脈、IPC、功耗與 workload 的綜合結果。

推理題：為何 branch prediction 猜錯不能只改 PC？

錯路徑指令可能已進入多個 stages。雖然它們通常尚未 retirement，但必須從 pipeline 清除，避免寫 register/memory 或拋出不該發生的 exception；再從正確 target 重新 fetch。

推理題：同一 ISA 的兩顆 CPU 為何效能可差很多？

它們可有不同 clock、pipeline width/depth、out-of-order window、cache/TLB、branch predictor、execution units 與 memory controller。ISA 只約束 architectural behavior，不規定這些 microarchitectural 資源。

5.1 最有價值的改善順序

  1. 改變演算法複雜度或減少不必要工作。
  2. 改善資料布局與 locality，減少 cache miss、allocation、copy。
  3. 移除 loop-invariant work、昂貴呼叫與不必要 bounds checks。
  4. 增加 instruction-level parallelism，減少 dependency chain。

5.2 Compiler optimization 的邊界

編譯器必須遵守語言語意與可能的 alias。若兩個 pointer 可能指向同一位置，重排 load/store 可能改變結果；這會限制最佳化。restrict 是程式設計師提供的強契約，只有在確實不重疊時才能使用。

// 降低 dependency chain：四個 accumulator 提供更多 ILP
double sum4(const double *a, size_t n) {
    double s0 = 0, s1 = 0, s2 = 0, s3 = 0;
    size_t i = 0;
    for (; i + 3 < n; i += 4) {
        s0 += a[i]; s1 += a[i+1]; s2 += a[i+2]; s3 += a[i+3];
    }
    for (; i < n; ++i) s0 += a[i];
    return (s0 + s1) + (s2 + s3);
}

這個改寫可能改變 floating-point 加總順序，因此低位結果可能不同。最佳化不能只問「快不快」，也要明確定義允許的數值誤差。

5.3 CPE 與效能下限

Cycles per element（CPE） 適合描述大型 loop 的穩態成本。若 operation latency 形成單一 dependency chain，latency 會限制 CPE；若有多個獨立 operations，execution units 的 throughput 可能成為下限。Loop unrolling 同時可降低 branch/index overhead，並暴露更多獨立工作，但過度展開會增加 code size 與 register pressure。

  5. 剩餘高 bits 是 tag。到 set 3 比對兩條 valid lines 的 tag。

6.2 儲存技術與機械成本

SRAM 快且昂貴，常做 CPU cache；DRAM 密度較高，需要 refresh，做主記憶體。SSD 沒有 seek arm，但有 page/block、erase、wear leveling 與 write amplification；HDD 的 seek 與 rotational latency 讓隨機 I/O 遠慢於順序 I/O。實際 storage 還受 controller、queue、filesystem 與 page cache 影響。

6.3 為何 row-major 順序重要

C 的二維陣列按 row-major 連續配置。逐 row 掃描會充分使用每條 cache line；逐 column 在大矩陣上可能每次只用一個元素就跳到遠處。Matrix transpose 需要 blocking，讓輸入與輸出的小區塊同時留在 cache。

// cache-friendly：內層走連續記憶體
for (size_t i = 0; i < rows; ++i)
    for (size_t j = 0; j < cols; ++j)
        total += matrix[i][j];

Blocking 的推導

Transpose 同時讀 A 的 row、寫 B 的 column。若整張矩陣太大，兩邊 lines 不斷互相驅逐。Blocking 把矩陣切成可容納於 cache 的小 tile，在 tile 內完成更多工作後才移到下一塊。Tile 大小不是永遠 8×8；要依 line size、associativity、element size 與同時活躍資料選擇。

6.4 Write policy 與一致性

  • Write-through：每次寫 cache 同時更新下一層，簡單但流量大。
  • Write-back：先只改 cache line 並標 dirty，evict 時才寫回。
  • Write-allocate：write miss 先把 block 載入 cache；常搭配 write-back。
  • 多核心還要維持 cache coherence，避免核心對同一地址看到互相矛盾的值。

6.5 False sharing

兩個 thread 寫不同變數，但變數落在同一 cache line，coherence protocol 仍會讓 line 在核心間來回移動。解法可能是 padding、per-thread counters、批次合併；是否有效要以 counter 與 benchmark 驗證。

工作應用：資料結構比指令更重要 Pointer-heavy tree 容易產生 cache miss；連續 array、structure of arrays、arena allocation 常能提升 locality。資料庫的 B-tree、columnar format 與 vectorized execution 都是記憶體階層思維的延伸。
卡關：地址相同 set 就一定 miss 嗎？ 不一定。Set-associative cache 的同一 set 有 E 條 lines；只有同時需要的不同 tags 超過 associativity，或 replacement 剛好驅逐目標，才形成 conflict miss。還要考慮存取順序與其他 cache levels。
計算題：32 KiB、8-way、64-byte line 的 cache 有幾個 sets？

S = C / (E × B) = 32768 / (8 × 64) = 64 sets，因此 set index 需要 log2(64) = 6 bits，block offset 需要 6 bits。

推理題：為何「cache miss rate 較低」不保證程式較快？

它可能執行更多指令、增加分支、產生較長 dependency chain，或 miss 雖少但更昂貴。應看總 cycles、instructions、miss 數量與 miss penalty，而非單一比例。

計算題：AMAT 中 miss rate 從 5% 降到 4%，有多大影響？

若 hit time 1 cycle、miss penalty 100 cycles，原 AMAT 是 1 + .05×100 = 6 cycles，新 AMAT 是 5 cycles，改善約 16.7%。看似只少 1 percentage point，因 penalty 很大而有顯著影響。

推理題：Sequential access 為何仍可能 memory-bound？

Spatial locality 可降低 miss 數與提高 prefetch 效果，但若資料量遠大於 cache且每 byte 只做很少運算，總需求仍可能碰到 memory bandwidth 上限。這時需提高 arithmetic intensity、減少 bytes 或壓縮表示。

8.2 fork、exec、wait 的精確關係

  • fork 建立 child。父子有各自虛擬地址空間，初始內容看似相同，通常透過 copy-on-write 實作。
  • execve 不建立新 process；它用新程式替換目前 process image，PID 可維持。
  • waitpid 回收 child termination status。已終止但未回收的 child 是 zombie。
  • Orphan 會由系統指定的 reaper 收養；zombie 與 orphan 是不同概念。

if (pid == -1) {
    perror("fork");
    exit(EXIT_FAILURE);
}
if (pid == 0) {
    execlp("ls", "ls", "-l", (char *)NULL);
    _exit(127);                    // exec 失敗才會到這裡
}

Fork 題目不要心算，畫 process tree

8.3 Signal 是通知，不是可靠 queue

同類型 standard signal 通常不會無限排隊。Handler 可在主程式任意安全點插入，因此共享狀態與 I/O 都要非常保守。Handler 內只呼叫 async-signal-safe functions；常見模式是設置 volatile sig_atomic_t flag，或寫入 self-pipe/eventfd，讓正常 event loop 處理。

經典 race：先檢查條件，再睡眠 若 signal 在條件檢查後、pause 前抵達，程式可能永遠睡著。使用 signal mask 配合 sigsuspend，原子地解除遮罩並等待。

避免 lost wakeup 的標準時序

  1. 先 block 目標 signal，避免它在檢查前後任意插入。
  2. 建立 child / 更新共享的 signal-visible state。
  3. 在 loop 中檢查 predicate，例如尚有 foreground job。
  4. 用 sigsuspend 暫時套用解除該 signal 的 mask 並原子等待。
  5. 醒來後恢復原 mask，再次檢查 predicate。
卡關：Signal handler 是另一個 thread 嗎？ 一般不是。它是在某個 thread 的正常控制流中插入 handler，使用該 thread 的 context/stack（除非設 alternative signal stack）。正因為可打斷任意函式，handler 才不能安全呼叫大多數 library functions。

8.4 Job control

Shell 用 process group 表示 job；terminal 有一個 foreground process group。Ctrl-C 與 Ctrl-Z 由 terminal driver 發送給 foreground group。Shell 本身要避免被送出的 signal 終止，並用 setpgid、tcsetpgrp、waitpid 管理前景與背景工作。

8.5 Nonlocal jump

setjmp/longjmp 可保存並恢復控制環境，讓執行跳過一般 call/return 路徑。它可實作受限的錯誤逃生機制，但會繞過中間 stack frames 的正常 cleanup，也讓 local variable 規則變複雜。在 C++ 等有 destructors 的語言中不可拿它替代 exceptions。

工作應用：Graceful shutdown 收到 SIGTERM 後停止接新工作、通知 workers、等待有期限的 drain、flush 可安全落盤的狀態，最後退出。不要在 handler 直接做 logging、malloc、鎖或複雜 cleanup。
推理題：為何 fork 後父子都能看到先前開啟的 file descriptor？

兩邊各有 descriptor table entry，但它們指向同一個 kernel open file description，因此共享 file offset 與某些 status flags。若父子同時讀同一 regular file，誰先推進 offset 會影響另一方看到的位置。

推理題：execve 成功後為何不會返回？

成功時目前 process image 已被新程式替換，舊程式的 instruction、stack 與 call frame 不再存在，所以沒有原呼叫點可返回。只有失敗才回 -1 並設定 errno。

推理題：為何 shell 通常要在 fork 後、exec 前設定 redirection？

Child 可用 dup2 把自己的 stdin/stdout 指向檔案或 pipe，再 exec 新程式；exec 後新程式自然繼承這些 descriptors。Parent shell 的 descriptors 不被永久改變。

9.6 Garbage collection 的系統觀

Tracing collector 從 roots（register、stack、globals 等）出發找 reachable objects，未被找到者可回收。Conservative GC 把看似 pointer 的 bit pattern 也當 reference，可能保留其實已死亡的物件。Reference counting 回收及時、實作直覺，但需處理 cycle，且每次 reference update 都有成本。即使語言有 GC，仍可能因 cache、listener、global reference 造成邏輯 memory leak。

計算題：4 KiB page 的 offset 需要幾 bits？

4 KiB = 4096 = 2^12 bytes，因此 offset 是 12 bits。若 virtual address 是 48 bits，virtual page number 是其餘 36 bits，但實際 page-table 切分由架構定義。

設計題：free 時如何 O(1) 合併前後 blocks？

使用 boundary tags：header 記 size/allocated，free block 的 footer 重複 size，便可由目前 block 找前一個 footer與下一個 header。現代 allocator 常用「前一塊是否已配置」bit，讓 allocated blocks 不必保留 footer，以降低 overhead。

推理題：兩個 processes 的同一 virtual address 內容一定相同嗎？

不一定。各 process 有自己的 page-table mappings，同一 virtual address 可映射到不同 physical pages。只有明確共享的 mapping、共享 library code 或 fork 後尚未 COW 的 pages 才可能指向同一 physical backing。

設計題：Allocator 為何要設定 minimum block size？

Free block 必須至少容納 metadata，例如 header、footer、free-list prev/next pointers，並滿足 alignment。Split 若留下更小碎片，該空間永遠無法管理，反而破壞 heap traversal。

         └──> inode / vnode（檔案 metadata 與資料位置）

dup 或 fork 可讓多個 fd entries 指到同一 open file description。close 只移除一個 reference；最後一個 reference 消失時 kernel object 才真正釋放。

dup2 如何實作 shell redirection

int fd = open("out.txt", O_WRONLY | O_CREAT | O_TRUNC, 0644);
if (fd == -1) /* handle error */;
if (dup2(fd, STDOUT_FILENO) == -1) /* handle error */;
close(fd);                   // stdout 仍保有對 open file description 的 reference
execlp("ls", "ls", "-l", (char *)NULL);

新程式完全不必知道 redirection；它照常寫 fd 1。這展示了 Unix composition：Shell 改環境，application 遵守標準 descriptor 契約。

10.2 Robust I/O loop

int write_all(int fd, const void *buf, size_t count) {
    const char *p = buf;
    size_t left = count;
    while (left > 0) {
        ssize_t n = write(fd, p, left);
        if (n > 0) { p += n; left -= (size_t)n; continue; }
        if (n == -1 && errno == EINTR) continue;
        return -1;
    }
    return 0;
}

read 回傳 0 通常表示 EOF；正值可能少於要求 bytes，不能假設一次拿滿。Nonblocking fd 沒資料時可能回 EAGAIN/EWOULDBLOCK。Socket 寫入還要處理 peer close 與 SIGPIPE。

EOF 是「所有 writer references 都關閉」

Pipe reader 要收到 EOF，必須沒有任何 process 還持有 write end。Fork 後若 parent/child 忘了 close 不使用的 pipe ends，reader 可能永遠等不到 EOF。設計 pipeline 時，在每個 process 逐一列出要保留與立即關閉的 descriptors。

10.3 stdio 與 descriptor I/O 不可隨意混用

FILE* 有 user-space buffer，descriptor 有 kernel offset。混用時若沒有遵守同步規則，buffer 與 offset 可能不一致。fork 前未 flush 的 stdio buffer 也可能被父子各自 flush，造成重複輸出。

10.4 Metadata、atomicity 與 durability

  • rename 在同一 filesystem 內通常提供原子名稱替換，常用於安全更新檔案。
  • 成功 write 不等於資料已到持久媒體；需要依 durability 要求使用 fsync/fdatasync，並考慮 directory metadata。
  • O_APPEND 讓每次 write 的 offset 設定與寫入具原子語意，但一個 logical record 若拆成多次 write 仍可能交錯。

10.5 Buffered robust I/O

對 line-oriented protocol，可在 user space 維護一個 read buffer，底層以大區塊 read，上層提供 read-line/read-N 介面。這能減少 system calls，但每個 connection 必須有獨立狀態，並限制最大行長；EOF 前的最後一行即使沒有 newline，也要依 API 契約正確回傳。

工作應用：安全寫設定檔 在同 directory 建 temp file，寫完整內容，依需求 fsync temp，設定權限，rename 覆蓋目標，再依崩潰一致性需求 fsync directory。任何步驟失敗都保留舊版本。
卡關：close 成功是否代表資料安全落盤？ 不代表。它釋放 descriptor reference，錯誤回報與 durability 語意依 filesystem/OS 而異。若業務要求崩潰後仍存在，必須明確使用 sync API 並測試 power-loss/crash consistency。
推理題：為何 read(fd, buf, 4096) 回 100 不代表 EOF？

Pipe、terminal、socket、某些檔案系統或被 signal 打斷的情境都可能產生 short read。只有回 0 才表示當下的 stream EOF；協定層仍需知道要讀固定長度、delimiter 還是到 connection close。

推理題：父子各自 close 同一個 inherited fd，會互相讓對方立即失效嗎？

不會。Fork 後各有 descriptor table entry，close 只移除呼叫 process 的 reference。另一方仍可用自己的 fd，直到它也 close 或被 exec 的 close-on-exec 規則關閉。

設計題：讀固定 32-byte header 的函式何時才算成功？

應 loop 到累積 32 bytes；遇 EINTR 繼續；在拿滿前遇 EOF 應回報 truncated input，而非正常完整 header；其他 error 保留原因。若有 deadline/nonblocking，還要把「暫時沒資料」與永久失敗分開。

11.3 必須設計的 failure semantics

  • Timeout：connect、read、write、request deadline 分開定義；不是一個萬用數字。
  • Retry：只在錯誤可重試且操作具有 idempotency 或 request ID 去重時執行。
  • Backpressure：限制 connection、in-flight request、queue bytes，避免慢 downstream 讓記憶體無限成長。
  • Partial failure：連線斷掉時，client 未必知道 server 是否已完成操作。
  • Input validation：限制 header、body、nesting、數量與解碼時間，避免資源耗盡。

11.4 HTTP 的系統觀

HTTP 建立在 transport 之上。實務上要理解 connection reuse、head-of-line blocking、proxy/load balancer、TLS handshake、request body streaming 與 cancellation。Application timeout 應傳遞成 downstream deadline，避免 caller 已放棄但後端仍持續工作。

工作應用：debug 一個 timeout 先分 DNS、connect、TLS、server queue、application、downstream、response transfer。抓 client/server timestamps 與 correlation ID；用 packet capture 或 socket metrics 驗證 retransmission、zero window、reset，而不是把所有 timeout 當成「網路不穩」。
卡關：TCP reliable，為何 application 還要 checksum、request ID 或 retry？ TCP 的可靠性只涵蓋單一連線內 bytes 的傳送與排序。它不保證對方 application 完成處理、不保證跨重連的 exactly-once，也不防 application/storage corruption。更高層需求要由協定另外實作。
設計題：4-byte length prefix 的 parser 要檢查什麼？

必須讀滿 4 bytes、按指定 byte order 解碼、確認不超過 protocol max、確認轉成 size_t 不 overflow、避免 length + header overflow、設定 deadline，並以 loop 讀滿 payload。若 buffer 可被 attacker 控制，還要限制同時在途的總 bytes。

推理題：Server 的 accept 回傳新 fd 後，原 listening fd 還有什麼用？

Listening fd 繼續接收後續 connections；新 connected fd 只代表這一個 client-server flow。若誤把 listening fd 關掉，既有 connected sockets 可繼續，但無法再接受新連線。

設計題：Retry 何時會造成 duplicate operation？

Server 可能已完成操作但 response 在網路中遺失，client timeout 後重送。對非 idempotent 操作，使用 idempotency key 與 server-side result/dedup store，或提供可查詢操作狀態的 protocol。

12.2 Race condition 與 atomicity

counter++ 通常是 load、add、store，不是不可分割操作。Mutex 提供 mutual exclusion，還建立跨 thread 的 memory ordering。Atomic type 適合小型、明確的 state transition；多欄位 invariant 通常仍需要 lock 或不可變快照。

兩個 increments 如何遺失一次更新

初始 counter = 0
Thread A: load 0
Thread B: load 0
Thread A: add → 1
Thread B: add → 1
Thread A: store 1
Thread B: store 1
最後是 1，不是 2

Race condition 是結果依賴 timing；data race 在 C/C++ 等語言有更精確定義：不同 threads 對同一 memory location 的衝突存取缺少適當同步，其中至少一個是 write。Data race 可導致 undefined behavior。

12.3 Condition variable 正確模式

pthread_mutex_lock(&mutex);
while (!predicate()) {                 // 必須是 while
    pthread_cond_wait(&condition, &mutex);
}
consume_state();
pthread_mutex_unlock(&mutex);

wait 會原子地釋放 mutex 並睡眠，醒來後重新取得。使用 while 是因為 spurious wakeup、其他 thread 可能先消費條件，且 signal 代表「狀態可能改變」，不是把資源直接交給某個 waiter。

Bounded queue 的 state 與 predicates

// 同一 mutex 保護 buffer、head、tail、count
not_empty predicate: count > 0
not_full  predicate: count < capacity

producer:
  lock
  while (!not_full) wait(not_full_cv)
  insert item; count++
  signal(not_empty_cv)
  unlock

consumer:
  lock
  while (!not_empty) wait(not_empty_cv)
  remove item; count--
  signal(not_full_cv)
  unlock

Predicate 由共享 state 定義，不存在於 condition variable 裡。修改 predicate state 與 signal 的時序需配合 mutex，避免 waiter 錯過狀態。

12.4 Deadlock、livelock、starvation

Deadlock 的四個必要條件是 mutual exclusion、hold-and-wait、no preemption、circular wait。實務常以全域 lock ordering 打破 circular wait，也可減少巢狀鎖、縮短 critical section、使用 try-lock/timeout 與 runtime detection。

Livelock 是 threads 一直反應卻沒有進展；starvation 是某個工作長期拿不到資源。Fair queue、bounded retry with jitter、aging 能改善，但公平通常會付出 throughput 成本。

12.5 Semaphore 與經典同步問題

Counting semaphore 表示可用資源數；wait/P 取得一個，沒有資源時阻塞，post/V 歸還。Bounded buffer 可用 slots、items 兩個 semaphores 加一個 mutex。Readers-writers 問題展示 throughput 與公平的取捨：偏好 reader 可能餓死 writer，偏好 writer 也可能讓 reader 長期等待。

12.6 Thread safety 四層問題

  • Shared mutable state：明確 owner，或用 lock/atomic 保護。
  • Reentrancy：函式不依賴跨呼叫共享的可變狀態，signal handler 尤其嚴格。
  • Lifetime：避免 thread 還在使用物件時另一方 free。
  • Cancellation：被取消時 lock、resource、partial update 怎麼恢復。

12.7 Lock granularity 與可擴展性

一把大鎖容易證明 correctness，但 contention 高；細鎖可增加 parallelism，卻增加 lock ordering、lifetime 與組合操作難度。先用清楚的大鎖做對並量測，再依 profile 拆分。Sharding、per-thread state、immutable data、message passing 常比堆疊更多鎖更容易維護。

卡關：Atomic 是否等於 thread-safe？ 單一 atomic operation 不會自動保護跨多個變數或 read-modify-check sequence 的 invariant。例如 atomic balance 的「讀餘額足夠再扣款」仍需 CAS loop 或更高層同步；否則兩個操作可都先看到足夠餘額。
工作應用：Thread pool 的完整容量模型 除了 worker count，還要定義 bounded queue、enqueue timeout、拒絕策略、per-request deadline、shutdown drain、panic/exception 隔離與 metrics。Unbounded queue 只是把 overload 轉成高 latency 和 OOM。
推理題：增加 threads 為何可能變慢？

可能增加 context switch、lock contention、cache/TLB miss、memory bandwidth pressure 與 queueing。CPU-bound workload 的有效 parallelism 受 cores 與 serial fraction 限制；I/O-bound 才可能從更多 in-flight work 受益。

設計題：銀行轉帳要鎖兩個帳戶，如何避免 deadlock？

為每個帳戶定義穩定排序鍵，例如 account ID。任何轉帳都先鎖較小 ID，再鎖較大 ID，所有路徑遵守同一順序。若同帳戶轉帳只取一次鎖。還需在 critical section 內同時驗證餘額與更新兩邊，維持 invariant。

推理題：為何用 volatile 不能取代 mutex？

在 C 中，volatile 主要要求對該 object 的存取不要被一般方式省略，適合某些 memory-mapped I/O 或 signal 情境；它不提供跨 thread atomicity，也不建立完整的 synchronization/happens-before。使用 language atomics 或 mutex。

設計題：如何測出低機率 race，而不是加入 sleep 碰運氣？

使用 ThreadSanitizer、壓力測試、隨機排程/注入 yield、縮小 critical sequence、增加重複次數，並檢查 invariant。建立 barrier 讓 threads 同時到達敏感位置，比固定 sleep 更可重現。

10. restrict 用錯會怎樣？違反 no-alias 契約會造成 undefined behavior，編譯器可產生看似意外的結果。
11. Direct-mapped cache 的 E 是多少？E = 1；每個 set 只有一條 line。
12. Spatial locality 為何對 linked list 較差？節點可能分散配置，相鄰 traversal 不一定落在相鄰 cache lines。
13. Relocation entry 解決什麼？記錄哪個位置引用哪個 symbol，以及 linker 要用何種規則修補。
14. Section 與 segment 的差別？Section 偏向連結視角；segment 描述 loader 要映射的範圍與權限。
15. Zombie 還會執行嗎？不會；只保留 termination status 等資訊，等待 parent 回收。
16. Blocked signal 消失了嗎？沒有；它可成為 pending，但 standard signal 同類型通常只記一個 pending 狀態。
17. TLB 保存什麼？近期 virtual page 到 physical page 的轉譯與 permission 資訊。
18. malloc(0) 能否解參考？不能；回傳可能是 NULL 或可供 free 的 unique pointer，但沒有可用 payload。
19. dup2 常用在哪？Shell redirection，把 stdin/stdout/stderr descriptor 指向 pipe 或檔案。
20. EINTR 後一律重試安全嗎？要看 API 與是否已產生部分副作用；read/write loop 還需先處理正的 short count。
21. TCP 是否保證一次 send 對應一次 recv？不保證；TCP 只有 ordered byte stream，message framing 由 application 定義。
22. Listening socket 與 connected socket 差在哪？前者接收新連線；accept 回傳的後者承載特定 peer 的資料。
23. Mutex 除了互斥還提供什麼？建立 memory ordering / happens-before，使受保護資料的寫入對下一個持鎖者可見。
24. 為何 condition wait 必須在 while 中？處理 spurious wakeup，以及醒來後條件已被其他 thread 改變的情況。
題 1：一個 C global 變數從原始碼到執行時會經過哪些階段？

解答：Compiler 依 linkage 與初始化產生 symbol，放入適合的 section；未初始化或零初始化常進 BSS，非零初始化常進 data。Assembler 產生 object 與必要 relocation。Linker 解析同名定義、配置 section 地址並修補引用。Loader 依 program headers 建立 mappings；dynamic symbol 可能再由 dynamic loader 處理。執行時 CPU 用虛擬地址存取，經 TLB/page table 轉成 physical address，資料最後由 cache/DRAM 提供。

題 2：程式把 int length 與封包中的 unsigned 32-bit 長度相加後 malloc，可能有哪些漏洞？

解答：需考慮 byte order、signed/unsigned conversion、加法 overflow、轉成 size_t 的寬度、上限驗證、零長度語意與 allocation failure。安全順序是先用固定寬度 unsigned 解碼，驗證 protocol maximum，再用 checked addition 算 header + payload，確認不超過 SIZE_MAX，最後配置。不能先加再檢查，因為值可能已 wrap。

題 3：某 loop 改成 branchless 後 branch-miss 大降，但時間不變，如何解釋？

解答：可能新增更多 instructions、形成 dependency chain、增加 loads、限制 vectorization，或原本 branch prediction 已足夠好。也可能瓶頸在 memory bandwidth。比較 cycles、instructions、IPC、cache miss 與輸入分布；確認 benchmark 沒被其他階段主導。

題 4：fork 後 child 修改大型陣列，RSS 為何突然增加？

解答：Fork 後 pages 初始以 copy-on-write 共享。Child 寫入每個 page 時觸發 protection fault，核心建立私有 physical page 並複製內容，因此 touched pages 的 resident memory 增加。只讀不會產生同等複製；觀察 minor faults 可驗證。

題 5：為何在 signal handler 中呼叫 printf 可能 deadlock？

解答：Main flow 可能在執行 stdio 並持有內部 lock 時被 signal 打斷，handler 再進入 printf 嘗試取得同一 lock。stdio 不是 async-signal-safe。Handler 應只做安全操作，例如設定 flag 或向 pipe 寫固定資料。

題 6：兩個 process 使用同一個 inherited fd 寫 log，會發生什麼？

解答：它們的 fd entries 指向共享 open file description，因此共享 offset。單次 write 的交錯語意取決於檔案類型與 flags；若一則 log 拆成多次 write，內容可能交錯。stdio buffer 在 fork 前若未 flush，還可能重複。常見設計是單一 logging process/thread、每筆一次 bounded write，或使用具 record semantics 的 IPC。

題 7：Cache simulator 的 LRU 應在何時更新？

解答：每次 hit 與 miss 後填入 line 都算一次 access，該 line 成為 most recently used。Eviction 選 valid lines 中最久未使用者。Modify operation 常代表 load 後 store，因此是兩次 access：第一次可能 miss/eviction，第二次必定 hit（在單執行緒模型且中間無其他 access）。

題 8：Allocator 的 heap checker 至少應驗證哪些 invariant？

解答：每個 block 對齊；size 合法且不越過 heap；header/footer 一致（若有 footer）；相鄰 free blocks 已依策略 coalesce；free list pointers 位於 heap 且前後一致；free list 不重複、不含 allocated block；線性掃描發現的 free blocks 與 free list 集合一致；prologue/epilogue 合法。Checker 不應使用被測 allocator 自己的 malloc。

題 9：Thread pool queue 為何不能無上限？

解答：當到達率長期高於服務率，queue 會持續成長。每個 request 消耗 memory，等待時間也增長；client timeout 後 server 仍做已無價值的工作，最後可能 OOM。Bounded queue 使 overload 早期可見，搭配拒絕、shed load、deadline 與 backpressure 維持系統可恢復性。

題 10：TCP client send 成功後斷線，能否確定 server 已完成資料庫寫入？

解答：不能。Send/write 成功通常只表示資料已被本機 kernel 接受；即使 peer 收到，也不代表 application 已處理，更不代表 transaction commit。需要 application response 定義完成點；若 response 遺失，client 仍處於 ambiguous outcome。以 idempotency key、operation status query 或 exactly-once-like dedup protocol 處理重試。

題 11：ASan 沒報錯是否代表沒有 memory bug？

解答：不代表。它只檢查被 instrumented 且實際執行到的路徑，對某些 intra-object overflow、自訂 allocator、未 instrumented library、data race 或邏輯 lifetime 問題可能無能為力。搭配高覆蓋測試、UBSan/TSan、static analysis、fuzzing 與 invariant checks。

題 12：設計一個調查 p99 latency regression 的最小實驗計畫。
  1. 固定版本、機器與 request distribution，確認 regression 可重現。
  2. 把 p50/p95/p99 與 throughput、error rate 一起看，排除負載差異。
  3. 以 tracing 分解 queue、CPU、lock、syscall、downstream 時間。
  4. 對 slow samples 取得 profile/counters，而非只看平均 profile。
  5. 比較 commits 或 feature flags，一次隔離一個變因。
  6. 提出可被推翻的假說，例如 LLC misses 增加；用 perf counter 驗證。
  7. 修正後做 correctness、steady-state、overload 與 rollback 驗證。
